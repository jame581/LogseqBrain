# v0.10.0 — Digest layer: cheap recall, honest coverage (design)

**Date:** 2026-07-25
**Status:** approved (design)
**Theme:** give every project and task page a small, always-current summary surface so recall costs ~1 KB instead of ~27 KB — and make every partial read declare what it left out, so Claude cannot silently reason from a fragment.

## Motivation

### Measured, not estimated

Taken from the maintainer's live graph at `E:\Loqsec\ClaudeBrain` on 2026-07-25 (49 pages / 1.27 MB, 68 journals / 131 KB — ~350k tokens if ever read whole):

| Page | Total | `## Session Log` | Share |
|---|---|---|---|
| `Projects___Unicorn-Globus.md` | 108.9 KB (558 lines) | 89.5 KB, 49 entries | **82 %** |
| `Projects___Timinute.md` | 87.1 KB | 39.7 KB | 46 % |
| `Projects___SELOS.md` | 59.8 KB | 29.6 KB | 50 % |
| `Projects___HalfLife-Caffeine.md` | 56.2 KB | 21.3 KB | 38 % |
| `Projects___LogseqBrain.md` | 26.5 KB | 15.5 KB | 58 % |
| `Tasks___CRMGM-1994.md` | 108.0 KB | — | *no size governor at all* |

Three conclusions:

1. **The Session Log is the whale.** Every other optimization is rounding error beside it. v0.9.0's rotation exists but is suggestion-only at 64 KB, and `Unicorn-Globus` sailed past it to 108.9 KB.
2. **The budget unit is wrong.** `skills/_shared/section-locator.md` targets "brief load ≤ 80 lines". Bullets in this graph average **195 bytes** and the longest is **2,187 chars**, so 80 lines is ~4k tokens on a fat page and ~800 on a thin one. Lines are not a token budget.
3. **Partial reads are silent.** Brief mode shows Claude 3 of 49 session entries with no marker that 46 are missing, so the model reasons as if it holds the whole history. This is a mechanical cause of confabulation, not a model quirk.

### What Logseq OG can and cannot do for us

Logseq split in 2026: **OG** (markdown) moved to <https://github.com/logseq/og> and entered **maintenance mode** — security and Electron upgrades only, no new features ever. The DB (SQLite) version beta landed 2026-07-13 at the original repo. This plugin targets **OG only**.

OG parses markdown into an in-memory DataScript DB and caches it at `~/.logseq/graphs/logseq_local_<encoded-path>.transit` (5.8 MB for this 1.4 MB graph, live-updated). But:

- There is **no local API or CLI for file graphs**. `@logseq/cli` serves DB graphs only; the plugin API runs only inside the desktop app.
- `logseq/nbb-logseq` + `cldwalker/logseq-query` *can* parse a file graph and run Datalog from the command line, but `lq` is self-described alpha and would put a node/nbb runtime under a plugin whose identity is *markdown skills, no runtime code*. **Rejected.**

So all leverage for OG lives in **file layout + property discipline + ripgrep** — which is stable forever and needs no dependencies. Concretely, four OG primitives are currently under-used:

| Primitive | Current use | Available leverage |
|---|---|---|
| Block properties (`key:: value`) | page-top only | Any bullet's properties are greppable; one `rg` yields a whole-graph table. `:property-pages/enabled? true` is already set. |
| Block refs (`id::` + `((uuid))`) | none | Cross-project decisions are physically duplicated into `Decisions.md` today |
| Namespaces | `Projects/X/SessionArchive`, `.../Tasks` | Any unbounded section should become a child page |
| `{{query}}` | none | Live human-facing dashboards; already whitelisted by the `code-in-braces` rule |

v0.10.0 exploits the first. The second and third are noted as future work (§8).

### The roadmap gate has resolved

`ROADMAP.md` says v0.10.0's contents wait "until Logseq's roadmap clarifies which is closest to ready." It has now clarified, in the negative: **storage abstraction**, **DB plugin API**, and **headless CLI sync** are all dead for OG. There is nothing left to wait for.

Decisions in this design were made with the maintainer on 2026-07-25.

## 1. The digest contract

A new shared reference, `skills/_shared/digest.md`, is the single source of truth for the digest. Both new surfaces are **additive** — no existing content moves.

### 1.1 Page-top properties

Appended to the existing property block of project and task pages. Existing properties (`type::`, `status::`, `created::`, `last-updated::`, and any page-specific ones) are untouched.

```
type:: project
status:: active
created:: 2026-04-15
last-updated:: 2026-07-25
focus:: Hangfire unification — phase 2 of 4
next:: CRMGM-2016 rollout to STAGE
open:: backup retention window undecided
digest-updated:: 2026-07-25
```

| Property | Meaning | Rules |
|---|---|---|
| `focus::` | what is being worked on now | one line, ≤ 120 bytes, required |
| `next::` | the single immediate next action | one line, ≤ 120 bytes, required |
| `open::` | open questions / blockers | one line, ≤ 120 bytes, **omitted entirely when none** — never written as `open:: none` |
| `digest-updated::` | `yyyy-MM-dd` the digest was last written | required; the drift signal for §5.2 |

Property values are ordinary content and obey **every** existing compose invariant in `skills/_shared/logseq-format.md` — backticks for code, escaped `#` before numbers/hex, namespaced `[[Tasks/…]]` links, markdown links not `[[file://]]`. brain-save's step-5 self-check already scans composed blocks; the digest block is simply another composed block.

Two OG-specific notes recorded so they are not rediscovered later: `:property-pages/enabled? true` means `focus` / `next` / `open` become Logseq property pages (cosmetic, accepted); and `:property/separated-by-commas` is unset in the reference graph, so commas in a value are **not** parsed as page refs.

### 1.2 The `## Digest` section

Placed immediately after the property block, **before** `## Overview`.

```markdown
- ## Digest
  - Product catalog integration platform: SAP / STEP PIM → SQL + Mongo → REST APIs
  - Now: unifying 5 Hangfire schedulers behind one dispatcher (phase 2 of 4)
  - Binding: 2026-04-17 DEV Mongo removed; whole-DEV decommission still undecided
  - Hazard: GLOPRICE-399 migration overlaps Price Checker hosts
  - Map: Session Log 89 KB (49 entries) · Decisions 12 · Implementation 4 KB · Archive [[Projects/Unicorn-Globus/SessionArchive]] · page 109 KB
```

**Slots** — 3 to 6 bullets, in this order, each optional except the first and the map:

1. **Identity** — what this project or task *is*. The most stable line; changes rarely.
2. **Now** — current state and phase.
3. **Binding** — decisions that still constrain the work, dated. Prefer a *pointer* (`2026-04-17 DEV Mongo removed`) over restated reasoning; the reasoning lives in `## Decisions` and is one grep away.
4. **Hazard** — gotchas, overlaps, traps.
5. *(free slot)* — anything the above does not cover.
6. **Map** — see §1.3. Always last, always present.

**Hard cap: 800 bytes** for the whole section including the map bullet. With the property block (~400 B), digest *content* for a brief load is therefore **under 1 KB by construction**.

Task-page digests use the same shape but run thinner (typically identity + now + map), since task pages have no fixed template.

### 1.3 The map bullet is computed, not authored

The map is the load-bearing anti-hallucination device: it tells Claude *what it does not have*, and doubles as the index for escalation (§3). Because prose can be wrong in ways arithmetic cannot, the map is **measured at write time**, never written from memory. One Bash call per save:

```bash
p="pages/Projects___<Name>.md"
total=$(wc -c < "$p")
sl=$(awk '/^(- )?## Session Log/{f=1;next} f&&/^(- )?## /{exit} f' "$p" | wc -c)
dec=$(awk '/^(- )?## Decisions/{f=1;next} f&&/^(- )?## /{exit} f' "$p" \
      | grep -E '^\s+- ' | grep -cvE '^\s+- (_.*_$|[a-z][a-z0-9-]*:: )')
ent=$(awk '/^(- )?## Session Log/{f=1;next} f&&/^(- )?## /{exit} f' "$p"       | grep -cE '^\s+- \[?\[?[0-9]{4}-[0-9]{2}-[0-9]{2}')
```

Session-entry bullet formatting varies across the real graph (several pages return an entry count of 0 despite tens of KB of log). Therefore: **byte figures are authoritative and always emitted; entry counts are best-effort and omitted when the count is 0 but the section has content.** A map that says `Session Log 39 KB` is correct and useful; one that says `0 entries` is a lie and must not be written.

Sections absent from the page are omitted from the map rather than reported as zero.

**Every figure is scoped to its own section.** An unscoped `ent` grep counts dated `## Decisions` bullets as session entries — and the Binding slot explicitly recommends dated decision lines, so that is the normal case, not an edge case. `dec` likewise counts decision *entries*, excluding their `context::` / `rationale::` / `status::` children and italic placeholder stubs. Caught during implementation: the first draft of this snippet reported 51 sessions on a 49-session fixture.

> **Deviation from the approved mock-up, flag if unwanted:** the mock-up carried `sessions:: 49 (3 shown in brief; 46 in Session Log)` as a page-top property. That is folded into the map bullet instead, so the counts have exactly one home and cannot drift against themselves. The information is unchanged; only its location moved.

## 2. Load: digest-only with lazy escalation

`skills/brain-load/SKILL.md` brief mode is replaced:

1. Resolve path; match project (`references/matching.md`, unchanged).
2. **One** `Read(page, offset 0, limit 20)` — captures the property block (~8 lines) and the whole `## Digest` (heading + ≤ 6 bullets). The bound is line-based only because it is an *upper* bound on a region whose bytes are already capped by §1.2; it may overshoot a few lines into `## Overview`, which is acceptable and bounded. Measured cost is therefore ≤ ~2 KB, of which ≤ 1 KB is digest content.
3. If `## Digest` is absent → **fall back to v0.9.0 brief mode verbatim** (section-targeted Properties + Overview + Current Plan + last 3 session entries) and offer to build a digest (§5.1). Every existing graph therefore keeps working before backfill ever runs.
4. Present the digest plus an explicit **coverage statement** (§4).
5. Journey-log line: `loaded [[Projects/<Name>]] (digest)`.

**Full mode** is unchanged in what it reads, but gains byte-denominated budgets and coverage statements (§4). It remains the escape hatch when the user wants everything in the window at once.

Load of general context (`load brain`) is unchanged — `Index.md` is 2.7 KB and already an excellent entry point.

## 3. The escalation ladder

New shared reference `skills/_shared/escalation.md`. The digest is a floor, not a ceiling: when the conversation needs something the digest does not carry, Claude fetches it — narrowly, and out loud.

| Level | Action | Cost | Announced? |
|---|---|---|---|
| 0 | Digest (always loaded) | ~1 KB | — |
| 1 | Consult the map — does the thing even exist here? | 0 | no |
| 2 | Targeted grep on the page: `rg -n "<term>" <page>` | ~100 B | **yes** |
| 3 | Bounded read around the hits (± 10 lines) | ~1–2 KB | yes |
| 4 | Whole-section read — only if that section is ≤ 8 KB | ≤ 8 KB | yes |
| 5 | Whole-page read | up to 109 KB | **explicit user consent required** |

Rules:

- **Escalation is announced from level 2 up** — "checking the Session Log for the Hangfire decision…". Silent escalation would reintroduce the invisible-cost problem this version exists to fix.
- **Never skip a level.** If a grep answers the question, stop there.
- **Level 5 is consent-gated**, mirroring the plugin's existing suggestion-only discipline for writes.

## 4. Truncation honesty

A stated contract, enforced in three places:

1. **Structural** — the digest map declares what exists and how big it is, at load time, before Claude reasons about anything.
2. **Mechanical** — `skills/_shared/section-locator.md` gains the rule: *any* `Read` bounded by `limit` must report what it covered — `read 4 KB of 89 KB of ## Session Log (entries 47–49 of 49)`. If the bound cannot be characterized, say so rather than omitting the statement.
3. **User-facing** — brain-load's summary carries a coverage line: *"Loaded digest for Unicorn-Globus. 89 KB / 49 sessions of log not read — ask and I'll grep it."*

Rewrite of `section-locator.md`, same file, four changes:

- Budgets re-denominated in **bytes**: digest brief load ≤ 1 KB; full load ≤ 24 KB soft ceiling with explicit overflow reporting; whole-page reads consent-gated.
- The measured facts recorded (~195 B average bullet, 2,187 B maximum) so the line-count trap is not reintroduced.
- A **measure-before-read** step: `wc -c` and `grep -c` are effectively free and tell you whether a section is worth reading whole. Measure, then choose the level.
- The truncation-honesty rule above.

## 5. Maintenance

Two paths, deliberately asymmetric: a cheap one that runs constantly, and an expensive one that restores correctness.

### 5.1 Refresh on save (cheap, unconditional)

A new step in `skills/brain-save/SKILL.md`, inserted after step 8 (Meta) so the two derived-surface refreshes sit together: **step 9 = digest refresh**, **step 10 = Index one-liner refresh** (the existing step 9), with post-write verify, journey log, and confirmation shifting to 11–13.

The step:

1. Recompute the map (§1.3) — one Bash call.
2. Rewrite `focus::` / `next::` / `open::` / `digest-updated::` in the page-top block.
3. Rewrite the `## Digest` bullets from the same session knowledge that produced the Session Log entry and Current Plan.
4. If the page has **no** digest, build one now from what is already in context (§5.3).

**Unconditional, by design.** This is the exact lesson v0.9.0 recorded for the Index one-liner: *rot comes precisely from "only when it changed" judgment calls*. Added cost is ~1 read + 1 edit per save.

The composed digest passes through brain-save's existing step-5 compose self-check and the step-11 post-write verify like any other written block, plus the `oversized-digest` compose check (§6).

### 5.2 Rebuild from source (expensive, correcting)

Refresh-on-save only ever knows about the current session, so over dozens of sessions a digest slowly sheds facts that are old but still true. Rebuild is the counterweight: it re-derives the digest **from the page**.

**Triggers:** lazily on first touch of a page with no `digest-updated::`; on drift (`digest-updated::` more than 30 days behind `last-updated::` → *suggest*, never silently spend); via brain-doctor batch (§5.3); or explicitly ("rebuild digest for X").

**Procedure:** read section-by-section under the §4 byte budgets, never the whole file at once. Read `## Session Log` **tail-first** — recent entries carry more signal per byte — and stop once the slots are filled or the budget is spent. Where an archive page exists, read the archive's own digest rather than its contents.

### 5.3 Backfill: lazy by default, batch on request

The live graph has 11 project pages and 34 task pages with no digest.

- **Lazy (default)** — a page with no digest gets one built the first time it is loaded or saved. Cost is spread out and paid only for pages actually in use; dead pages never cost anything. On a *save*, the digest is built from context already gathered, so it is nearly free; on a *load*, the fallback path (§2 step 3) offers the rebuild rather than performing it uninvited.
- **Batch (opt-in)** — `brain-doctor` gains a guided backfill flow modelled on v0.9.0's task-status backfill: report every page missing a digest with its size, propose the work with an estimated cost, and build on one confirmation.

## 6. New hygiene rules

Added to `skills/_shared/hygiene-rules.md` following the existing entry schema. All three scope to `pages/Projects___*.md` and `pages/Tasks___*.md`; pages with `type:: session-archive` and the singleton pages (`Index`, `Meta`, `Decisions`) are out of scope.

### `missing-digest`
- **severity:** data-quality · **enforced-at:** scan · **auto-fixable:** report
- **detection:** page lacks a `digest-updated::` line in its first 12 lines, or lacks a `## Digest` heading.
- **remediation:** report with the page's byte size; offer rebuild (§5.2). Report-tier because building a digest is a judgment call with real token cost — never auto-spent.

### `stale-digest`
- **severity:** data-quality · **enforced-at:** scan · **auto-fixable:** report
- **detection:** `digest-updated::` is more than 30 days behind `last-updated::`.
- **remediation:** report with both dates; suggest rebuild.

### `oversized-digest`
- **severity:** data-quality · **enforced-at:** compose, scan · **auto-fixable:** safe-only
- **detection:** bytes between `## Digest` and the next `## ` heading exceed 800; or any of `focus::` / `next::` / `open::` exceeds 120 bytes.
- **remediation:** the safe subset is **compose-time only** — brain-save recompresses its own composed digest before writing, exactly as it silently corrects its own mechanical violations today. At scan time the rule is **report-only**: trimming content already on disk is never safe to automate. (Same scoping discipline as `malformed-property`.)

## 7. brain-status becomes one ripgrep

Today's dashboard costs roughly 11 greps plus ~33 reads across 11 project pages. With digest properties in place it becomes a single call:

```bash
rg "^(type|status|last-updated|focus|next|open|digest-updated):: " pages/ \
   -g "Projects___*.md" -g "Tasks___*.md"
```

One result set, ~200 tokens, containing every project's status, focus, next action, open blocker, and freshness. Staleness rules (`skills/_shared/staleness.md`) apply to `last-updated::` exactly as they do now; task grouping by `status::` (v0.9.0) is unchanged and now comes from the same single call.

**Fallback:** a project whose page has no digest properties falls back to today's per-page reads *for that project only* — a partially-backfilled graph degrades per page, not wholesale.

This is a latency win as much as a token win: ~44 tool round-trips collapse to 1.

## 9. Validation

No runtime, no tests — same as prior versions: a fixture-graph pass (the pattern from v0.9.0's `3a13d97`) plus a manual round-trip against `E:\Loqsec\ClaudeBrain`, with the new items added to `CONTRIBUTING.md`. The before/after byte measurements are themselves the acceptance test.

1. **Backward compatibility first.** `load SELOS` against an un-backfilled page → v0.9.0 brief mode, unchanged behaviour, plus a digest offer. Nothing regresses before backfill.
2. **Digest build.** Rebuild the digest for `Projects/Unicorn-Globus` → section ≤ 800 B, all slots sane, map figures match `wc -c` / `grep -c` run independently.
3. **The headline number.** `load Unicorn-Globus` → **one** Read, ≤ ~2 KB, versus 27 KB today. Record the actual figure.
4. **Coverage honesty.** The same load states the omission ("89 KB / 49 sessions not read"). Every bounded read in the session carries a coverage statement.
5. **Escalation.** Ask a question answerable only from the Session Log → Claude announces, greps, reads a bounded region, and does *not* read the page whole.
6. **Refresh.** A normal save → `digest-updated::` moves to today, map figures update, post-write verify clean.
7. **Status.** `brain status` → one ripgrep, 11 projects, correct staleness flags; then with one project's digest properties removed, that project alone falls back.
8. **Doctor.** Scan a graph with a fat digest and an old `digest-updated::` → `oversized-digest` and `stale-digest` report; `missing-digest` lists exactly the un-backfilled pages.
9. **Batch backfill.** Run it over the 45 project + task pages; confirm cost is reported before work begins and that it is genuinely one confirmation.
10. **Task pages.** `Tasks___CRMGM-1994.md` (108 KB) gets a digest and loads in one Read at ≤ ~2 KB.

### Success criteria

- Brief load of `Projects/Unicorn-Globus`: **27 KB → ≤ ~2 KB in one Read** (≥ 92 % reduction)
- `brain status` across 11 projects: **~44 tool calls → 1–2**
- No partial read anywhere in the plugin is silent about its coverage
- A graph with zero digests behaves exactly as v0.9.0 does today

## 10. Not in scope

- **Block refs (`id::` + `((uuid))`) for decisions** — would end the physical duplication between project pages and `Decisions.md`. Real value, orthogonal to the digest; deferred so v0.10.0 changes one thing well.
- **`{{query}}` dashboards** — human-facing only, no token effect for Claude. Future candidate.
- **Retrieval rethink** (drop project pre-loading entirely, grep purely on demand). §3's ladder is a bounded step in that direction; the full change should wait until digests have been in real use.
- **Automatic (non-suggested) session-log rotation**, and rotation for task pages. The digest makes page size much less painful to *read*, which lowers the urgency; revisit once §9's measurements are in.
- **A `Digest` child page per project** — considered and rejected: an extra file and an extra read, and the human has to navigate away to see it.
- **nbb-logseq / `logseq-query` runtime** — rejected in Motivation; a node/nbb dependency contradicts the plugin's no-runtime identity, and `lq` is alpha.
- **Logseq DB version support** — see the roadmap re-scoping in §8.
