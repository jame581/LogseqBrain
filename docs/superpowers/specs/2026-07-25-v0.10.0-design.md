# v0.10.0 — Digest layer: cheap recall, honest coverage (design)

**Date:** 2026-07-25
**Status:** approved (design)
**Theme:** give every project and task page a small, always-current summary surface so recall costs ~1 KB instead of ~27 KB — and make every partial read declare what it left out, so Claude cannot silently reason from a fragment.

## Motivation

### Measured, not estimated

Taken from the maintainer's live graph at `E:\Loqsec\ClaudeBrain` on 2026-07-25 (49 pages / 1.27 MB, 68 journals / 131 KB — ~350k tokens if ever read whole):

| Page | Total | `## Session Log` | Share |
|---|---|---|---|
| `Projects___Unicorn-Globus.md` | 108.9 KB (558 lines) | 89.5 KB, 49 entries | **82 %** |
| `Projects___Timinute.md` | 87.1 KB | 39.7 KB | 46 % |
| `Projects___SELOS.md` | 59.8 KB | 29.6 KB | 50 % |
| `Projects___HalfLife-Caffeine.md` | 56.2 KB | 21.3 KB | 38 % |
| `Projects___LogseqBrain.md` | 26.5 KB | 15.5 KB | 58 % |
| `Tasks___CRMGM-1994.md` | 108.0 KB | — | *no size governor at all* |

Three conclusions:

1. **The Session Log is the whale.** Every other optimization is rounding error beside it. v0.9.0's rotation exists but is suggestion-only at 64 KB, and `Unicorn-Globus` sailed past it to 108.9 KB.
2. **The budget unit is wrong.** `skills/_shared/section-locator.md` targets "brief load ≤ 80 lines". Bullets in this graph average **195 bytes** and the longest is **2,187 chars**, so 80 lines is ~4k tokens on a fat page and ~800 on a thin one. Lines are not a token budget.
3. **Partial reads are silent.** Brief mode shows Claude 3 of 49 session entries with no marker that 46 are missing, so the model reasons as if it holds the whole history. This is a mechanical cause of confabulation, not a model quirk.

### What Logseq OG can and cannot do for us

Logseq split in 2026: **OG** (markdown) moved to <https://github.com/logseq/og> and entered **maintenance mode** — security and Electron upgrades only, no new features ever. The DB (SQLite) version beta landed 2026-07-13 at the original repo. This plugin targets **OG only**.

OG parses markdown into an in-memory DataScript DB and caches it at `~/.logseq/graphs/logseq_local_<encoded-path>.transit` (5.8 MB for this 1.4 MB graph, live-updated). But:

- There is **no local API or CLI for file graphs**. `@logseq/cli` serves DB graphs only; the plugin API runs only inside the desktop app.
- `logseq/nbb-logseq` + `cldwalker/logseq-query` *can* parse a file graph and run Datalog from the command line, but `lq` is self-described alpha and would put a node/nbb runtime under a plugin whose identity is *markdown skills, no runtime code*. **Rejected.**

So all leverage for OG lives in **file layout + property discipline + ripgrep** — which is stable forever and needs no dependencies. Concretely, four OG primitives are currently under-used:

| Primitive | Current use | Available leverage |
|---|---|---|
| Block properties (`key:: value`) | page-top only | Any bullet's properties are greppable; one `rg` yields a whole-graph table. `:property-pages/enabled? true` is already set. |
| Block refs (`id::` + `((uuid))`) | none | Cross-project decisions are physically duplicated into `Decisions.md` today |
| Namespaces | `Projects/X/SessionArchive`, `.../Tasks` | Any unbounded section should become a child page |
| `{{query}}` | none | Live human-facing dashboards; already whitelisted by the `code-in-braces` rule |

v0.10.0 exploits the first. The second and third are noted as future work (§8).

### The roadmap gate has resolved

`ROADMAP.md` says v0.10.0's contents wait "until Logseq's roadmap clarifies which is closest to ready." It has now clarified, in the negative: **storage abstraction**, **DB plugin API**, and **headless CLI sync** are all dead for OG. There is nothing left to wait for.

Decisions in this design were made with the maintainer on 2026-07-25.

## 1. The digest contract

A new shared reference, `skills/_shared/digest.md`, is the single source of truth for the digest. Both new surfaces are **additive** — no existing content moves.

### 1.1 Page-top properties

Appended to the existing property block of project and task pages. Existing properties (`type::`, `status::`, `created::`, `last-updated::`, and any page-specific ones) are untouched.

```
type:: project
status:: active
created:: 2026-04-15
last-updated:: 2026-07-25
focus:: Hangfire unification — phase 2 of 4
next:: CRMGM-2016 rollout to STAGE
open:: backup retention window undecided
digest-updated:: 2026-07-25
```

| Property | Meaning | Rules |
|---|---|---|
| `focus::` | what is being worked on now | one line, ≤ 120 bytes, required |
| `next::` | the single immediate next action | one line, ≤ 120 bytes, required |
| `open::` | open questions / blockers | one line, ≤ 120 bytes, **omitted entirely when none** — never written as `open:: none` |
| `digest-updated::` | `yyyy-MM-dd` the digest was last written | required; the drift signal for §5.2 |

Property values are ordinary content and obey **every** existing compose invariant in `skills/_shared/logseq-format.md` — backticks for code, escaped `#` before numbers/hex, namespaced `[[Tasks/…]]` links, markdown links not `[[file://]]`. brain-save's step-5 self-check already scans composed blocks; the digest block is simply another composed block.

Two OG-specific notes recorded so they are not rediscovered later: `:property-pages/enabled? true` means `focus` / `next` / `open` become Logseq property pages (cosmetic, accepted); and `:property/separated-by-commas` is unset in the reference graph, so commas in a value are **not** parsed as page refs.

### 1.2 The `## Digest` section

Placed immediately after the property block, **before** `## Overview`.

**Post-launch correction (wave B, 2026-07-26):** stated generally, this reads "before the first `## ` section, whatever it is called." Task pages have no fixed template and often carry no `## Overview` at all, so anchoring the rule to a heading name that doesn't always exist was under-specified. `skills/_shared/digest.md` and `skills/brain-save/SKILL.md` step 9 now say so explicitly.

```markdown
- ## Digest
  - Product catalog integration platform: SAP / STEP PIM → SQL + Mongo → REST APIs
  - Now: unifying 5 Hangfire schedulers behind one dispatcher (phase 2 of 4)
  - Binding: 2026-04-17 DEV Mongo removed; whole-DEV decommission still undecided
  - Hazard: GLOPRICE-399 migration overlaps Price Checker hosts
  - Map: Session Log 87 KB (47 entries) · Active Tasks 10 KB · Current Plan 3 KB · Decisions 2 KB (2) · Archive [[Projects/Unicorn-Globus/SessionArchive]] · page 107 KB
```

**Post-launch correction (wave E, 2026-07-26):** this map line is now derived from the page's real sections, not a fixed field list — see the wave E note under §1.3 below.

**Slots** — 3 to 6 bullets, in this order, each optional except the first and the map:

1. **Identity** — what this project or task *is*. The most stable line; changes rarely.
2. **Now** — current state and phase.
3. **Binding** — decisions that still constrain the work, dated. Prefer a *pointer* (`2026-04-17 DEV Mongo removed`) over restated reasoning; the reasoning lives in `## Decisions` and is one grep away.
4. **Hazard** — gotchas, overlaps, traps.
5. *(free slot)* — anything the above does not cover.
6. **Map** — see §1.3. Always last, always present.

**Hard cap: 800 bytes** for the whole section including the map bullet. With the property block (~400 B), digest *content* for a brief load is therefore **under 1 KB by construction**.

Task-page digests use the same shape but run thinner (typically identity + now + map), since task pages have no fixed template.

### 1.3 The map bullet is computed, not authored

The map is the load-bearing anti-hallucination device: it tells Claude *what it does not have*, and doubles as the index for escalation (§3). Because prose can be wrong in ways arithmetic cannot, the map is **measured at write time**, never written from memory. One Bash call per save:

```bash
p="pages/Projects___<Name>.md"
total=$(wc -c < "$p")
sl=$(awk '/^(- )?## Session Log/{f=1;next} f&&/^(- )?## /{exit} f' "$p" | wc -c)
dec=$(awk '/^(- )?## Decisions/{f=1;next} f&&/^(- )?## /{exit} f' "$p" \
      | grep -cE '^\s+- \[?\[?[0-9]{4}-[0-9]{2}-[0-9]{2}')
ent=$(awk '/^(- )?## Session Log/{f=1;next} f&&/^(- )?## /{exit} f' "$p"       | grep -cE '^\s+- \[?\[?[0-9]{4}-[0-9]{2}-[0-9]{2}')
```

Session-entry bullet formatting varies across the real graph (several pages return an entry count of 0 despite tens of KB of log). Therefore: **byte figures are authoritative and always emitted; entry counts are best-effort and omitted when the count is 0 but the section has content.** A map that says `Session Log 39 KB` is correct and useful; one that says `0 entries` is a lie and must not be written.

Sections absent from the page are omitted from the map rather than reported as zero.

**Every figure is scoped to its own section.** An unscoped `ent` grep counts dated `## Decisions` bullets as session entries — and the Binding slot explicitly recommends dated decision lines, so that is the normal case, not an edge case. `dec` keys off the same dated-headline shape as `ent`, mirroring the Decision Entry Template (`{{date}}: {{decision_title}}`) — it counts `yyyy-MM-dd`-prefixed bullets, not lines in general. **Post-launch correction (wave A, 2026-07-26):** the first shipped cut excluded only property children (`context::` etc.) and italic stubs, so a free-form child under a decision — a `**Consequences:**` sub-list, say — was still counted as if it were its own decision, reporting `5` for a 2-decision section. Keying off the dated headline instead fixes that and, as a consequence, inherits `ent`'s honesty rule: an undated decision entry is not counted, so `dec` is best-effort and omitted (not reported as `0`) when the section has content. Caught during implementation: the first draft of this snippet reported 51 sessions on a 49-session fixture.

**Post-launch correction (wave E, 2026-07-26 — live validation):** the field list above (`Session Log`, `Decisions`, `Implementation`, `Archive`, `page`) shipped as a fixed set, and a real page outgrew it. Measured live on `Projects___Unicorn-Globus.md` (109,786 B, 10 real sections): `## Active Tasks` was the page's **second-largest section** (10,590 B) and never appeared in the map at all, so `brain-load`'s "not read" statement — which reads as a complete account of what was skipped — silently omitted a section holding 10% of the page. The map is now **derived from the page's actual section map**, not the fixed list: enumerate every `## ` heading (excluding `## Digest` itself), measure each, keep the ones at or above a **1 KB threshold** (below that, noise), sort largest first, and annotate `Session Log`/`Decisions` with their counts when they clear the threshold. On the same page this now surfaces `Session Log 87 KB (47 entries) · Active Tasks 10 KB · Current Plan 3 KB · Decisions 2 KB (2) · page 107 KB` — 119 bytes, comfortably inside the 800 B cap. If more sections clear the threshold than the cap allows, the smallest above-threshold ones are dropped first (the list is already sorted largest-first) and the map says `+N more`; sections that never cleared 1 KB were never candidates and don't count toward `N`. `skills/_shared/hygiene-rules.md`'s `stale-map` (§6) now parses whatever labels a Map actually claims and diffs each against the measured section of that name, rather than checking four fixed positions.

**Post-launch correction (wave E, 2026-07-26 — live validation):** `page` needed a second pass that the other figures don't. Writing the digest is itself a write to the page — the property-block Edit and the `## Digest` Edit both change the file's own byte count — so a `page` figure computed once, before those edits, and never revisited is stale the instant the write lands. Measured live: a Map computed before a first-digest write claimed `page 106 KB`; the file measured 109,786 B (107 KB) immediately after. That crossed a KB boundary, and the 1,242 B drift exceeded `stale-map`'s 1,024 B KB-tier tolerance — a correctly-computed Map, false-flagged as stale by write order, and tolerance had already been widened twice for this same figure. `skills/_shared/digest.md` now closes the gap the way `brain-init` already closes it for `{{page_size}}`: re-measure the page *after* writing, and Edit `page` again if the rounded figure changed. `skills/brain-save/SKILL.md` step 9 numbers this as an explicit sub-step, not a footnote. No other map figure needs it — each measures a section these edits don't touch.

**Post-launch correction (wave E1, 2026-07-26 — final review, real task pages):** every wave-E fixture was a project page; a pass against the maintainer's actual task pages (`Tasks___CRMGM-1937/1904/1994.md`) found the field-derivation and fitting mechanics above still broken on that shape of page, in four ways:

- **Entry counting missed a whole entry form.** Two task pages write every Session Log entry as `- ### 2026-05-25 — …` rather than a plain dash-bullet. The scoped grep (`^[[:space:]]+- \[?\[?[0-9]{4}-…`) cannot match the `###` form at all, so it undercounted a 12-entry section as 5 and a 13-entry section as 0 — silently, because the honesty rule above only omits on a count of exactly 0, and 5 is not 0. The pattern is now `^[[:space:]]*- (#{2,6} +)?\[?\[?[0-9]{4}-…`, matching either form, plus a new cross-check: if the dated-entry count still comes back lower than the section's own top-level child-bullet count (properties and italic stubs excluded), omit the count rather than publish a number already known to be a floor.
- **The label/figure split broke on real headings.** Task pages have no fixed template — free-form `## ` headings carrying dates, version numbers, and PR numbers (`2026-04-23 — Step 2 isolated, real root cause found`, `PROD 2.6 — EXECUTED 2026-06-01 …`). `stale-map`'s parser recovered the label by cutting at the first space-then-digit, which is exactly what these headings are full of — one heading produced a false "no such section" finding, and a second, differently-worded heading beginning with the same dated prefix silently collapsed to the *same* cut label, so its own byte diff never ran (the mis-parse `continue`d past it). The Map is now serialized as `<label> | <figure>` — a reserved separator, not a positional guess — and `stale-map` splits on it. Labels are also capped at 40 characters (`…` marker) since task-page headings run long; `stale-map` resolves a truncated label by unique-prefix match, reports "matches more than one section" if the prefix is ambiguous, and reports a duplicate label as its own finding rather than keying two clauses to one section.
- **The 800 B fitting budget didn't reserve for its own tail.** `+N more`, the `Archive` pointer, and the page total were appended *after* fitting candidates to budget, not before — so a page with many above-threshold candidates could fit 800 B of *candidates* and then blow past the cap appending the parts that were never optional. Measured on `Tasks___CRMGM-1937.md`: 808 B. `skills/_shared/digest.md`'s fitting procedure now reserves worst-case room for all of it — including a new reconciling residual, next — before accepting the first candidate.
- **The Map degenerated at both size extremes on task pages.** A page with many above-threshold sections (`CRMGM-1937.md`, 13 of them, most with long free-form headings) produced a Map that was almost entirely heading prose, squeezing the digest's own prose slots to two bullets, while 4,121 B of sub-threshold sections were named nowhere. A page with almost no structure (`CRMGM-1994.md`, 108 KB, 2 sections total) produced a Map so short it named only one section, though in that particular case the two sections already summed to the page total with nothing hidden. The 40-character label cap (above) fixes the first failure directly — capping every label freed enough room that all 13 candidates fit in 736 B, no `+N more` needed. The second failure is fixed by a new **reconciling residual** clause, `+N smaller sections, X KB`, summarizing every section that never cleared the 1 KB threshold — present whenever at least one exists, reserved for like `Archive` and `page`, never dropped for space.

`skills/_shared/hygiene-rules.md`'s `stale-map` also picked up two independent fixes from the same pass: the KB tolerance was a symmetric `±1024 B` band, but `digest.md` mandates *truncation*, which is one-sided — a claim of `87 KB` against a true 88,100 B section (which truncates to `86 KB`, one tier down) drifted only 988 B, under the old band, and passed as if correct. The tolerance is now the one-sided `0 <= measured − claimed_floor <= 1023`. Separately, a claimed section that has since shrunk under the 1 KB inclusion floor is now flagged even when its stated figure still diffs "correctly" — `digest.md` says such a section should have been dropped from the Map, not left in at a shrunk-but-arithmetically-consistent figure.

> **Deviation from the approved mock-up, flag if unwanted:** the mock-up carried `sessions:: 49 (3 shown in brief; 46 in Session Log)` as a page-top property. That is folded into the map bullet instead, so the counts have exactly one home and cannot drift against themselves. The information is unchanged; only its location moved.

## 2. Load: digest-only with lazy escalation

`skills/brain-load/SKILL.md` brief mode is replaced:

1. Resolve path; match project (`references/matching.md`, unchanged).
2. **One** `Read(page, offset 0, limit 20)` — captures the property block (~8 lines) and the whole `## Digest` (heading + ≤ 6 bullets). The bound is line-based only because it is an *upper* bound on a region whose bytes are already capped by §1.2; it may overshoot a few lines into `## Overview`, which is acceptable and bounded. Measured cost is therefore ≤ ~2 KB, of which ≤ 1 KB is digest content.

   **Post-launch correction (wave A, 2026-07-26):** task pages have no fixed template, so the property block above the digest is not actually bounded — enough task-specific properties (5 extra properties was enough in the reproduction) push `## Digest` far enough down the file that `limit 20` lands past the Map bullet, returning several plausible digest bullets and no Map. This is silent corruption of the coverage contract, not a visible failure: the digest still *looks* complete. The read is now a check, not a one-shot: **the result must contain a `Map:` bullet**; if it does not, re-read with a larger `limit` or `grep -nE '^(- )?## '` for the exact span, and never present a digest whose Map was not actually seen.

   **Post-launch correction (wave C, 2026-07-26):** the wave-A fix asserted the *cause* of a missing Map (bound too short) but named no terminal case for the page genuinely not having one — `missing-digest` also passed such a page (see §6), so nothing in the plugin ever said "this page has no Map." Step 2 now has a terminal branch: if a read bounded to the *whole* `## Digest` span (not a bigger guess at `limit`) still shows no `Map:`, the page lacks one — say so, treat coverage as unknown, and offer to build a digest, same as the no-`## Digest` fallback in step 3.
3. If `## Digest` is absent → **fall back to v0.9.0 brief mode verbatim** (section-targeted Properties + Overview + Current Plan + last 3 session entries) and offer to build a digest (§5.1). Every existing graph therefore keeps working before backfill ever runs.
4. Present the digest plus an explicit **coverage statement** (§4).
5. Journey-log line: `loaded [[Projects/<Name>]] (digest)`.

**Post-launch correction (wave B, 2026-07-26):** the drift trigger in §5.2 (`digest-updated::` more than 30 days behind `last-updated::`) was implemented only in brain-doctor's scan, even though load's step-2 Read already returns both dates in the same 20-line window. `brain-load` now compares them as part of step 2 and, on drift, adds a line to the step-4 coverage statement suggesting (never performing) a rebuild. The fallback path's digest offer (step 3) was also reworded to quote the bytes that fallback read actually measured rather than the fixed "~4 KB to under 1 KB" figure from the original draft, consistent with this design's own "measured, not estimated" thesis.

**Post-launch correction (wave E, 2026-07-26 — live validation):** step 3's "last 3 session entries" is denominated in entries, which assumes average-sized bullets. Measured live on a 59.8 KB page with no digest (`Projects___SELOS.md`): the last 3 entries alone cost 9,098 B, and the fallback's other three components (property block 1,148 B + Overview 5 bullets 1,055 B + Current Plan 3,682 B) brought the total to 14,983 B — nearly double `section-locator.md`'s stated ≤ 8 KB fallback target. The tail is now **byte-bounded**: last 3 entries *or* ~4 KB, whichever is smaller — take fewer entries (never zero) when recent ones run large, and say how many of how many were read. On the same SELOS page this reads 1 of 12 entries (2.8 KB) instead of 3 of 12 (9.1 KB), landing the fallback total at 8.7 KB. `section-locator.md`'s "Token-frugality target" no longer states a single ≤ 8 KB ceiling the fallback can silently exceed; it states the per-component budget (property + Overview + Current Plan + byte-bounded tail ≈ ≤ 16 KB worst case) and names the byte-bounded tail as what keeps real pages well under it.

**Full mode** is unchanged in what it reads, but gains byte-denominated budgets and coverage statements (§4). It remains the escape hatch when the user wants everything in the window at once.

**Post-launch correction (wave E2, 2026-07-26 — final review):** "Last 10 Session Log entries" (§Load Modes) shipped entry-denominated — exactly the defect wave E byte-bounded the fallback's "last 3" for, just at 10-entry scale. Measured live, the raw cost was **25.4 KB** (`Projects___Unicorn-Globus.md`, 47 entries), **27.5 KB** (`Projects___SELOS.md`, 12 entries), and **36.8 KB** (`Projects___Timinute.md`, 12 entries) — every one already past the entire 24 KB ceiling by itself, before Overview/Current Plan/Implementation/Decisions are read at all. The tail is now bounded the same way as the fallback's, at the larger per-section cap: last 10 entries *or* ~8 KB, whichever is smaller (shrink-until-under-cap, never zero). Bounding lands the same three pages at 3.9 KB (1 of 47), 6.3 KB (2 of 12), and 6.9 KB (2 of 12). Because the ceiling can still be exceeded by the other, independently-capped full-mode components summing past it, full mode now also **measures its total before reading** and, when that total would exceed 24 KB, states the figure and asks — the consent gate `skills/_shared/escalation.md` rule 3 already requires for a 109 KB whole-page read; a `load <project> full` costing tens of KB had no equivalent courtesy before this fix. "Report the overflow" remains the honesty rule for whatever gap remains after the bound and the ask, not a substitute for either.

Load of general context (`load brain`) is unchanged — `Index.md` is 2.7 KB and already an excellent entry point.

## 3. The escalation ladder

New shared reference `skills/_shared/escalation.md`. The digest is a floor, not a ceiling: when the conversation needs something the digest does not carry, Claude fetches it — narrowly, and out loud.

| Level | Action | Cost | Announced? |
|---|---|---|---|
| 0 | Digest (always loaded) | ~1 KB | — |
| 1 | Consult the map — does the thing even exist here? | 0 | no |
| 2 | Targeted grep on the page: `rg -n "<term>" <page>` | ~100 B | **yes** |
| 3 | Bounded read around the hits (± 10 lines) | ~1–2 KB | yes |
| 4 | Whole-section read — only if that section is ≤ 8 KB | ≤ 8 KB | yes |
| 5 | Whole-page read | up to 109 KB | **explicit user consent required** |

Rules:

- **Escalation is announced from level 2 up** — "checking the Session Log for the Hangfire decision…". Silent escalation would reintroduce the invisible-cost problem this version exists to fix.
- **Never skip a level.** If a grep answers the question, stop there.
- **Level 5 is consent-gated**, mirroring the plugin's existing suggestion-only discipline for writes.

## 4. Truncation honesty

A stated contract, enforced in three places:

1. **Structural** — the digest map declares what exists and how big it is, at load time, before Claude reasons about anything.
2. **Mechanical** — `skills/_shared/section-locator.md` gains the rule: *any* `Read` bounded by `limit` must report what it covered — `read 4 KB of 89 KB of ## Session Log (entries 47–49 of 49)`. If the bound cannot be characterized, say so rather than omitting the statement.
3. **User-facing** — brain-load's summary carries a coverage line: *"Loaded digest for Unicorn-Globus. 89 KB / 49 sessions of log not read — ask and I'll grep it."*

Rewrite of `section-locator.md`, same file, four changes:

- Budgets re-denominated in **bytes**: digest brief load ≤ 1 KB; full load ≤ 24 KB soft ceiling with explicit overflow reporting; whole-page reads consent-gated.
- The measured facts recorded (~195 B average bullet, 2,187 B maximum) so the line-count trap is not reintroduced.
- A **measure-before-read** step: `wc -c` and `grep -c` are effectively free and tell you whether a section is worth reading whole. Measure, then choose the level.
- The truncation-honesty rule above.

## 5. Maintenance

Two paths, deliberately asymmetric: a cheap one that runs constantly, and an expensive one that restores correctness.

### 5.1 Refresh on save (cheap, unconditional)

A new step in `skills/brain-save/SKILL.md`, inserted after step 8 (Meta) so the two derived-surface refreshes sit together: **step 9 = digest refresh**, **step 10 = Index one-liner refresh** (the existing step 9), with post-write verify, journey log, and confirmation shifting to 11–13.

The step:

1. Recompute the map (§1.3) — one Bash call.
2. Rewrite `focus::` / `next::` / `open::` / `digest-updated::` in the page-top block.
3. Rewrite the `## Digest` bullets from the same session knowledge that produced the Session Log entry and Current Plan.
4. If the page has **no** digest, build one now from what is already in context (§5.3).

**Unconditional, by design.** This is the exact lesson v0.9.0 recorded for the Index one-liner: *rot comes precisely from "only when it changed" judgment calls*. Added cost is ~1 read + 1 edit per save.

The composed digest passes through brain-save's existing step-5 compose self-check and the step-11 post-write verify like any other written block, plus the `oversized-digest` compose check (§6).

### 5.2 Rebuild from source (expensive, correcting)

Refresh-on-save only ever knows about the current session, so over dozens of sessions a digest slowly sheds facts that are old but still true. Rebuild is the counterweight: it re-derives the digest **from the page**.

**Triggers:** lazily on first touch of a page with no `digest-updated::`; on drift (`digest-updated::` more than 30 days behind `last-updated::` → *suggest*, never silently spend); via brain-doctor batch (§5.3); or explicitly ("rebuild digest for X").

**Post-launch correction (wave B, 2026-07-26):** the drift trigger shipped detectable only in brain-doctor's on-demand scan (`stale-digest`, §6), even though both dates it compares are already in hand at load time (brain-load's single digest Read) and at status time (brain-status's single ripgrep) — the comparison is free in both places and the realistic trigger (a cross-device save from an older plugin version, or a hand-edit) is exactly what those two skills see first. `skills/brain-load/SKILL.md` and `skills/brain-status/SKILL.md` now both surface drift proportionately — one line each — pointing at this section's rebuild procedure; neither rebuilds without confirmation. Also added the "rebuild digest for X" trigger phrase to `brain-doctor`'s `description:` field — it was documented here and nowhere routed.

**Procedure:** read section-by-section under the §4 byte budgets, never the whole file at once. Read `## Session Log` **tail-first** — recent entries carry more signal per byte — and stop once the slots are filled or the budget is spent. Where an archive page exists, read the archive's own digest rather than its contents.

**Post-launch correction (wave E2, 2026-07-26 — final review, real task pages):** the procedure above is entirely project-shaped (Overview → Identity, Current Plan → Now, Decisions → Binding, Session Log tail-first) and, measured against the spec's own §9.10 acceptance page, had no step that applied to a task page at all. `Tasks___CRMGM-1994.md` (108,143 B) has only `## Overview` (1,335 B) and `## Notes` (106,526 B — 98% of the page); none of the five project-shaped steps names `## Notes`, so a rebuild that only knew those names would derive almost nothing from a page that is almost nothing else. `skills/_shared/digest.md` now carries an explicit second branch for task-shaped pages (no `## Overview` / `## Current Plan` / `## Session Log` template): enumerate the page's real sections via the same derivation the Map already performs, read the largest one or two under the per-section cap (tail-first, using the byte-bounded tail recipe, when a candidate is over cap), and derive Identity/Now from what is actually there. On `CRMGM-1994.md` this reads the property block + `## Overview` whole (1,335 B) + a 3-entry tail of `## Notes` (5,670 B) = **7,261 B total**, never the 106.5 KB section whole. `brain-doctor`'s guided-backfill cost estimate (§5.3) picked up the matching fix — it previously summed the five project-shaped sections unconditionally, which quotes a number with no basis for a batch that includes task pages.

### 5.3 Backfill: lazy by default, batch on request

The live graph has 11 project pages and 34 task pages with no digest.

- **Lazy (default)** — a page with no digest gets one built the first time it is loaded or saved. Cost is spread out and paid only for pages actually in use; dead pages never cost anything. On a *save*, the digest is built from context already gathered, so it is nearly free; on a *load*, the fallback path (§2 step 3) offers the rebuild rather than performing it uninvited.
- **Batch (opt-in)** — `brain-doctor` gains a guided backfill flow modelled on v0.9.0's task-status backfill: report every page missing a digest with its size, propose the work with an estimated cost, and build on one confirmation.

## 6. New hygiene rules

Added to `skills/_shared/hygiene-rules.md` following the existing entry schema. All four scope to `pages/Projects___*.md` and `pages/Tasks___*.md`; pages with `type:: session-archive` and the singleton pages (`Index`, `Meta`, `Decisions`) are out of scope.

### `missing-digest`
- **severity:** data-quality · **enforced-at:** scan · **auto-fixable:** report
- **detection:** page lacks a `digest-updated::` line in its first 12 lines, or lacks a `## Digest` heading.
- **remediation:** report with the page's byte size; offer rebuild (§5.2). Report-tier because building a digest is a judgment call with real token cost — never auto-spent.
- **Post-launch correction (wave C, 2026-07-26):** the shipped detection accepted any page with a `## Digest` heading and a `digest-updated::` line as "has a digest," even if the section's `Map:` bullet — a required slot (§1.2) — was itself missing. Every one of `missing-digest`, `stale-digest`, and `stale-map` passed such a page (`stale-map`'s own `[ -n "$map" ] || continue` guard skips it outright), so a digest with no Map was invisible to the whole rule set. `missing-digest` now also fails a page whose `## Digest` span has no `Map:` bullet — a digest without a Map is missing, not shorter. `skills/brain-load/SKILL.md` step 2 and `skills/_shared/section-locator.md` step 1 gained the matching terminal case: once a read is bounded to the *whole* `## Digest` span and still shows no Map, that means the page genuinely lacks one, not that the bound was too short — say so, treat coverage as unknown, and offer a rebuild, rather than looping on ever-larger `limit`s forever.

### `stale-digest`
- **severity:** data-quality · **enforced-at:** scan · **auto-fixable:** report
- **detection:** `digest-updated::` is more than 30 days behind `last-updated::`.
- **remediation:** report with both dates; suggest rebuild.

### `stale-map` (wave A, 2026-07-26 — added post-launch)
- **severity:** data-quality · **enforced-at:** scan · **auto-fixable:** report
- **detection:** pure arithmetic, not a date proxy. `digest-updated::` guards a *date*; it says nothing about whether the Map's *byte* claims still hold. The gap showed up concretely with rotation (§10 originally deferred automating rotation, but even the existing suggestion-only rotation moves ~80 KB out of a page while touching none of the three existing digest rules): recompute the same scoped figures `stale-digest`'s companions already compute (`skills/_shared/digest.md`'s Map snippet), parse what the page's own `Map:` bullet claims, and diff. A claimed figure off from the measured one by more than a rounding step is stale.
- **remediation:** report the mismatched figures (claimed vs. measured) and suggest rebuild, same report-tier discipline as `missing-digest` / `stale-digest`.
- **Post-launch correction (wave C, 2026-07-26):** two gaps found on a 22-page fixture matrix. First, "a rounding step" had shipped as a *proportional* tolerance (`~5% of measured, floor 20B`), which is the wrong shape for a value that rounds to whole KB — proportional tolerance shrinks below the actual rounding error on small pages (12 of 22 correctly-rounded fixture pages false-positived, including the spec's own `Implementation 4 KB` example at line 98) and widens past it on large ones (an 89 KB Session Log tolerated ~4.5 KB of undetected drift). Rounding error for a KB-denominated figure is **constant** — up to 1023 B if truncated, up to 512 B if rounded to nearest — regardless of section size, so the tolerance is now derived from the *unit the Map claims*: 1024 B for a `KB` figure, 20 B for a bare-byte figure. Second, the rule never diffed the entry count in `(N entries)` — the figure `brain-load`'s coverage statement leads with — so a Map claiming `(49 entries)` against a 5-entry section passed silently. `stale-map` now also computes `ent` (identical scoping to `skills/_shared/digest.md`'s snippet) and flags an exact mismatch — entry counts have no rounding step — while still honoring the omit-when-zero-but-nonempty rule from `digest.md`, so a Map that correctly omits the count is not compared.
- **Post-launch correction (wave D, 2026-07-26 — not previously logged here):** the byte-denominated tier's 20 B tolerance was too tight for the `page` figure specifically — `brain-save` step 9 measures the page and *then* edits the Map bullet, so the claim goes stale by the bullet's own length delta the moment it lands (measured: 32 B on a fresh project's first save). Byte tier raised to **64 B** to absorb that.
- **Post-launch correction (wave E, 2026-07-26 — live validation):** wave D's 64 B byte-tier widening turned out not to be the actual fix, because the same self-reference error also hits `page` when it's KB-denominated (any page over 1 KB, i.e. almost every real project page) — and there the 1024 B KB tier doesn't automatically absorb it, contrary to what was assumed when wave D scoped the byte-tier fix to "sub-1 KB pages" only. Measured live: a pre-write `page 106 KB` claim against a 109,786 B post-write total drifted **1,242 B**, past even the 1024 B KB tier. Widening either tolerance a third time is not the fix — it would just hide a bigger version of the same bug on the next boundary crossing. The fix is procedural: `skills/_shared/digest.md` now re-measures the page *after* writing the digest edits and corrects `page` if it changed (the same measure-after-write pattern `brain-init` already uses for `{{page_size}}`), and `skills/brain-save/SKILL.md` step 9 numbers this explicitly. `stale-map`'s detection also generalized in the same pass: since the map's field list is now derived per page (§1.3's wave E note), the rule parses whatever labels a page's Map actually claims and measures the real section of that name, rather than checking four fixed positions (`Session Log`, `Implementation`, `Decisions`, `page`).
- **Post-launch correction (wave E1, 2026-07-26 — final review, real task pages):** four more gaps, all specific to task pages (see §1.3's wave E1 note for the producer-side half of this fix). (1) The label parser cut at the first space-then-digit, which breaks on task-page headings full of dates and version numbers — fixed by parsing on the Map's new reserved ` | ` separator instead of guessing where a label ends. (2) A label truncated for display (40-character cap) needs prefix resolution, not exact match — `stale-map` now resolves a `…`-suffixed claim against every real heading's own 40-character prefix, and reports "matches more than one section" if that's ambiguous. (3) Two clauses parsing to the identical label — the old parser would have silently keyed both to whichever section matched first — is now its own finding, and neither of that pair is diffed. (4) The KB tolerance was symmetric (`±1024 B`), but `digest.md` mandates truncation, which is one-sided: a claim of `87 KB` against a true 88,100 B section (truncates to `86 KB`, one tier down) drifted only 988 B — under the old band, and missed. The tolerance is now `0 <= measured − claimed_floor <= 1023`. A fifth, independent addition: a claimed section now measuring under the 1 KB inclusion floor is flagged even when its stated figure still diffs "correctly," since `digest.md` says such a section should already have been dropped from the Map.

**Byte-moving writes must remap the digest they invalidate.** Two shipped procedures move bytes without themselves being a "normal save," so §5.1's unconditional refresh doesn't cover them automatically: `skills/brain-save/references/rotation.md` gained a final step recomputing the Map on both the project page and the archive page after a confirmed rotation, and `brain-doctor`'s verify step (§6 above is its rule catalog; the flow itself lives in `skills/brain-doctor/SKILL.md`) now recomputes the digest of every page whose bytes changed during repair. Both are one sentence plus a pointer to §1.3 — `stale-map` is the safety net if either is skipped, not a replacement for doing it at the source.

**Post-launch correction (wave C, 2026-07-26):** both call sites had named this operation "refresh," but `digest.md` only defined Refresh (rewrite the prose from the session that produced it) and Rebuild (re-read the page). Neither fits: rotation and a doctor repair carry no session knowledge to refresh the prose from, and neither is expensive enough to justify a full Rebuild. `digest.md`'s "Building a digest" section now names a third, cheapest path — **Remap**: recompute only the Map bullet, leaving `digest-updated::` and every prose slot untouched — a Remap writes the Map, not the digest, and bumping the date would silence `stale-digest` for another 30 days on prose nobody touched. Both `rotation.md` step 6 and `brain-doctor`'s verify step now call it Remap by name instead of "refresh."

**Post-launch correction (wave E2, 2026-07-26 — final review):** the wave-C fix above says correctly that a Remap leaves `digest-updated::` alone (only the Map bullet is recomputed), but `rotation.md` step 6 and `brain-doctor`'s verify step had both shipped saying the opposite — "the Map bullet **and** `digest-updated::` are recomputed" — directly contradicting `digest.md`'s own canonical definition and this section's own restated rationale. Four files (`digest.md`, `rotation.md`, `brain-doctor/SKILL.md`, this spec) needed to agree on one behavior; `digest.md`'s version was correct (the two signals must stay orthogonal — `stale-map` guards the Map arithmetically, `stale-digest` guards the prose by date, and bumping the date on a byte-moving-only write would silence `stale-digest` for another 30 days on prose nobody touched), so the other three were corrected to match rather than the reverse.

### `oversized-digest`
- **severity:** data-quality · **enforced-at:** compose, scan · **auto-fixable:** safe-only
- **detection:** bytes between `## Digest` and the next `## ` heading exceed 800; or any of `focus::` / `next::` / `open::` exceeds 120 bytes.
- **remediation:** the safe subset is **compose-time only** — brain-save recompresses its own composed digest before writing, exactly as it silently corrects its own mechanical violations today. At scan time the rule is **report-only**: trimming content already on disk is never safe to automate. (Same scoping discipline as `malformed-property`.)
- **Post-launch correction (wave A, 2026-07-26):** the property-value half of this check (`grep -E ".{121,}"`) counts *characters*, and under a UTF-8 locale a multi-byte character (`—`, `·` — both appear in this file's own digest examples) counts as one `.`, so a value that is genuinely 121 bytes but only 120 characters silently passes. The section-size half already uses `wc -c` (byte-exact regardless of locale), so the two halves of one rule disagreed on the same machine. Fixed by forcing `LC_ALL=C` on the property grep so both halves agree.

## 7. brain-status becomes one ripgrep

Today's dashboard costs roughly 11 greps plus ~33 reads across 11 project pages. With digest properties in place it becomes a single call:

```bash
rg "^(type|status|last-updated|focus|next|open|digest-updated):: " pages/ \
   -g "Projects___*.md" -g "Tasks___*.md"
```

One result set, ~200 tokens, containing every project's status, focus, next action, open blocker, and freshness. Staleness rules (`skills/_shared/staleness.md`) apply to `last-updated::` exactly as they do now; task grouping by `status::` (v0.9.0) is unchanged and now comes from the same single call.

**Fallback:** a project whose page has no digest properties falls back to today's per-page reads *for that project only* — a partially-backfilled graph degrades per page, not wholesale.

**Post-launch correction (wave B, 2026-07-26):** the shipped version made this ripgrep both the content source *and* the page census, so a project page whose property block is damaged or missing produces zero hits and disappears from the dashboard entirely rather than falling back — the worst-shaped failure for a memory tool, since the user concludes the project isn't there. Fixed by keeping `ls pages/Projects___*.md` / `pages/Tasks___*.md` as an explicit first step and the authoritative census; the ripgrep above supplies content only. Any census file with zero ripgrep hits is now listed as "no properties — run brain-doctor" instead of being silently omitted. Digest-drift flagging (see §5.2's correction) was added to the same staleness step, since it reads off the same ripgrep result set at no extra cost.

This is a latency win as much as a token win: ~44 tool round-trips collapse to 1.
