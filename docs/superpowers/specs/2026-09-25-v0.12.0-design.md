# v0.12.0: Fewer round trips, for real (design)

**Date:** 2026-09-25
**Status:** approved (design), 2026-09-25 — all §10 decisions taken as recommended
**Plan:** `docs/superpowers/plans/2026-09-25-v0.12.0-fewer-round-trips.md`
**Theme:** v0.11.0 made every figure exact but did not deliver its call budget. The eval suite measured a digest load at **11** tool calls (target ≤ 4) and a save at **27** (target ≤ 13). This release closes that gap. It fixes the flag-parsing bug the evals exposed, which can write to the wrong graph. It collapses each skill's fixed sequence of helper calls into one call. It removes the reference reads a routine load or save does not need. The eval suite becomes the gate that proves it.

---

## Motivation

### Measured, not estimated

Measured in the v0.11.0 spec §8 post-launch annotation (eval suite, 2026-09-14, commit `82b24a0`, one run per case on the 2.4 KB fixture page `Projects/Demo`):

| Metric | v0.11.0 target | Measured |
|---|---|---|
| Digest-load tool calls | ≤ 4 | **11** |
| Save tool calls | ≤ 13 | **27** |
| New error-tier findings from saves | 0 | **0** ✓ |

There are two known structural causes. Both are recorded in the v0.11.0 spec:

1. **The load path cannot meet its own target.** brain-load mandates Skill, `info`, `digest`, `journal` and `activity`. That is already 5 calls under `cost.py`'s counting (from the Skill call onward, that call included), before any reply.
2. **The trailing `--graph` flag.** In 8 of 8 graph-using baseline runs, the model's first call that passed a graph wrote `brain info --graph ./graph`, with the flag after the subcommand. The dispatcher parses flags only before the command (`skills/_shared/bin/brain:496-503`):
   - **With no config** (the sandbox), the call exits 2 and the model retries with the flag first. That is one wasted call per skill run, at least.
   - **With `LOGSEQ_BRAIN_PATH` or a config set** (real use), the call **silently runs against the configured graph**. Reproduced: `brain activity "…" --graph <other>` wrote to the environment's graph and appended the text `--graph <other>` to the bullet. This is a correctness bug, not only a cost.

There are also three likely causes. They are not yet confirmed by a per-call breakdown; see §11, item 1:

3. **Reference reads on the routine path.** Every SKILL.md begins with "see `skills/_shared/run-brain.md`" (3.5 KB). brain-save also points to `categories.md`, `logseq-format.md` and `digest.md` on the routine path. Each Read is one call, and all of them are instruction bytes.
4. **Read-before-Edit.** Claude Code's Edit tool requires a prior Read of the file. A save edits three files (the page, `pages/Index.md` and today's journal), so it pays three Reads even though `brain` already printed the content it needs.
5. **Edit granularity.** A save today does up to 6 Edits on the page: Session Log, Current Plan, `last-updated::`, the digest properties, the digest prose and a task `status::`. The properties and `## Digest` are adjacent by contract (`digest.md` Surface 2), so they can be one Edit.

### Instruction bytes

There is a second v0.11.0 target: **≤ 25 KB of instructions read per save**. The eval suite did not measure it. Summing what brain-save's routine path points to gives about 38 KB:

## 1. Flag parsing

### 1.1 Rule

`--graph DIR` and `--graph=DIR` are recognised **anywhere** on the command line, before or after the subcommand and its arguments. A literal `--` ends flag recognition: everything after it is a positional argument, so `brain search -- --graph` searches for the string `--graph`.

The dispatcher strips the flag and its value in a pre-pass, then routes the rest as today. POSIX `sh` has no arrays, so the pre-pass rotates `"$@"` in place with no `eval`: take the count `n=$#`, then `n` times take `a=$1; shift`, and either consume it (with its value) as the flag or re-append it with `set -- "$@" "$a"`. Arguments keep their exact bytes, including spaces, quotes and a leading `-`. `--graph` given twice is an error: `--graph given twice`, exit 2.

### 1.2 Why "accept" and not "reject"

A trailing-flag rejection would also fix the wrong-graph write. But the evals show the model writes the trailing form every time, so rejection keeps the wasted retry call. Accepting it costs nothing and matches how the helper is actually called.

### 1.3 Defence in depth for `activity`

`brain activity` refuses text that begins or ends with a bare `--graph` word, with `activity text contains a --graph flag — pass it before the text`, exit 2. After §1.1 that can only happen through quoting mistakes, and a quoting mistake must not put flag text into the journal.

> **Planning correction (independent review, 2026-09-25):** an empty `--graph ""` / `--graph=` is refused. Today it falls through to the environment graph, which is the same wrong-graph bug. The guard checks the first and last word of the text, and applies to `--summary` text as well. Plan refinements 1, 2, 11.

## 2. Composite commands

Each composite runs, in one process, exactly the steps a skill already performs in sequence. It adds **no new write kinds**, except where §10 D1 is approved. Output is the concatenation of the sub-commands' output, each block headed by a `== <command>` line, so every existing coverage line and figure appears unchanged. The exit code is the worst of the parts, with 2 over 1 over 0. A part that exits 2 stops the run, and its reason is printed.

### 2.1 `brain load <page> [--mode digest|full]`

| Step | Same as |
|---|---|
| graph and version lines | `brain info` |
| property block, `## Digest`, `map:`/`digest:`/`drift:`/`staleness:` lines | `brain digest <page>` |
| today's mentions of the page, ~2 KB, with coverage | `brain journal <page>` |
| `activity: HH:MM loaded [[Projects/X]] (digest)` | `brain activity …` |

- **The activity line is written only when the page has a digest.** On `digest: missing`, the model runs the brief fallback reads (unchanged) and writes `(brief)` itself with `brain activity`. Otherwise the helper would log a load that has not finished.
- `--mode full` prints the full-mode byte budget computed from `brain sections` and writes `(full)`. The model still asks before reading when the budget is over 24 KB, as today.
- The target load becomes **Skill → `brain load` → reply**: 2 tool calls on a digest-bearing page, when `info` needs no ask-and-persist.

### 2.2 `brain save-begin <page> [--also FILE…]`

This does everything a save needs before its first Edit, in one call:

1. `info` lines.
2. The section table, and baselines for the page, `pages/Index.md`, today's journal, and every `--also` file (Meta, Decisions). It is the same as today's step 3 `brain sections … --baseline …`, with the two always-touched files implied.
3. The property block and `## Digest`, as in `brain digest` (the Refresh starts from the current prose).
4. The Session Log's newest entry: `tail … --entries 1 --max 4096`.
5. `Current Plan`: `read`, and over its 8 KB cap, `tail --max 8192`.
6. **Edit anchors:** the page's line in `pages/Index.md` (`index: <line> <text>`, or `index: missing`), and today's journal's `## Sessions` state (`sessions: absent | heading at <line>, last bullet at <line> | no journal`).

`Decisions` and `Implementation` are read only on demand, with `brain read`, as today.

### 2.3 `brain save-finish <page> [--summary "<text>" --index "<parenthetical>"]`

1. `digest <page> --apply`: writes the Map and reports caps.
2. `check` over **every file baselined by the last `save-begin`**. The model no longer lists them, so it can no longer forget one.
3. `activity "saved [[Projects/X]]"`, or `[[Tasks/X]]` for a task page.
4. Only with §10 D1 approved: `--summary` appends `- [[Projects/X]]: <summary>` under today's `## Sessions`, and `--index` replaces the parenthetical of the page's `pages/Index.md` one-liner. Both use the same verified single-change commit as `activity` (§2.5 of the v0.11.0 spec).

If `digest --apply` reports a cap overflow (`digest prose over cap`, `over: open:: …`), the model fixes the prose with one Edit and reruns `brain digest <page> --apply` alone. `save-finish` is not rerun, so the activity line is written only once.

### 2.4 Expected call counts

| Operation | v0.11.0 measured | v0.12.0 shape | Calls |
|---|---|---|---|
| Digest load | 11 | Skill → `load` | **2** |
| Save, D1 approved | 27 | Skill → `save-begin` → Read page (partial, for Edit) → Edit props + digest → Edit Current Plan → Edit Session Log → `save-finish --summary --index` | **7** |
| Save, D1 rejected | 27 | as above, plus Read + Edit for Index and for the journal | **11** |

Both save shapes leave room under 13 for one cap-fix loop, or a Decisions read and Edit.

### 2.5 Old commands stay

`info`, `digest`, `journal`, `sections`, `check` and `activity` stay as they are, for brain-doctor, brain-status, rotation and recovery paths. The composites are implemented as shell functions calling the existing `cmd_*` functions, not as new awk programs.

> **Planning correction (independent review, 2026-09-25):** the plan refines §2.1 and §2.3. Details are in its refinements 3–10, 12 and 13.
> - `save-finish` **validates before any write**: the text, the digest caps, and a dry-run Map for every digest-bearing page in the save. A refusal therefore leaves the graph untouched, and the same command can be rerun.
> - The activity line is deferred while the save has a new error-tier finding.
> - There is one manifest per page. Multi-page saves run begin → Edits → finish per page, in sequence.
> - Every digest-bearing `--also` page is remapped.
> - Absent files are skipped by the check, and the Sessions append is idempotent.
> - The Index one-liner applies to project pages only, found inside `## Projects` by its first link.
> - `load` detects a digest from the `map:` line.
> - `load --mode full` records no baselines, and leaves `(full)` to the model after its reads.
> - Text arguments are single-quoted by the skills, because inside double quotes the shell runs backticks before the helper sees them.

## 3. Instruction diet, part 2

### 3.1 Rule: the routine path reads nothing but its SKILL.md

A digest load and a progress-only save must be executable from their SKILL.md alone. References are for branches: no digest, a decision, a rotation, a finding, an unresolved graph.

| Change | Effect |
|---|---|
| Put the three-line invocation (the `sh "<base>/../_shared/bin/brain"` form, the PowerShell form, the stop message) **in each SKILL.md**. `run-brain.md` becomes the reference for rare commands only. | −1 Read and −3.5 KB on every skill run |
| brain-save step 4 already inlines the compose invariants. Drop the pointer to `logseq-format.md` on the routine path; keep it for normalization trouble (an Edit anchor that doesn't match). | −7 KB per save |
| Move the Refresh procedure brain-save needs (slot order, caps, "leave the Map alone") into brain-save step 8, which is already most of it. `digest.md` is read only for Rebuild and backfill. | −13.3 KB per save |
| Inline the Session Log entry format (the one category every save writes) from `categories.md` into brain-save. | −3.2 KB per save |

### 3.2 `digest.md` and `hygiene-rules.md` shrink by moving developer content out

- **`digest.md`** (13.3 KB → ~6 KB). The Map computation contract (section selection, KiB truncation, entry counting, label cutting, cap fitting) is now implemented and tested by `map.awk`. Skills never compute it. Move it to `docs/reference/digest-map.md` (not shipped). `digest.md` keeps scope, the two surfaces, the slots, and the Refresh / Remap / Rebuild paths.
- **`hygiene-rules.md`** (21.8 KB → ~12 KB). `brain check` and `brain lint` print a one-line `fix:` hint per rule, so a save never needs the catalog for a routine finding. Detection detail (regexes, masking, oracle evidence) moves to `docs/reference/lint-rules.md`. The catalog keeps, per rule: what it means, its tier, and the repair brain-doctor applies.

### 3.3 Size targets

| File | Now | Target |
|---|---|---|
| `brain-save/SKILL.md` | 8,759 | ≤ 10 KB (it absorbs §3.1; net per-save bytes fall) |
| `brain-load/SKILL.md` | 6,064 | ≤ 5 KB |
| `brain-status/SKILL.md` | 5,313 | ≤ 3 KB |
| `_shared/digest.md` | 13,288 | ≤ 6 KB |
| `_shared/hygiene-rules.md` | 21,846 | ≤ 12 KB |
| **Routine save, total instruction bytes** | ~38 KB | **≤ 12 KB** |
| **Routine load, total instruction bytes** | ~9.6 KB | **≤ 5 KB** |

Figures are bytes (`wc -c`), matching `LC_ALL=C`.

> **Planning correction (independent review, 2026-09-25):** the `digest.md` ≤ 6 KB and `hygiene-rules.md` ≤ 12 KB targets cannot be met without moving content that shipped skills (brain-doctor, brain-init, rotation) act on. That content must stay shipped. The targets are restated as **≤ 9 KB** and **≤ 16 KB**. Neither file is on the routine path any more; the routine-path totals above are the figures that count. brain-status reaches ≤ 3 KB by moving Analytics to `references/analytics.md`, not by cutting it.

> **Implementation note (Task 12, 2026-09-25):** `digest.md` is 9,043 B, which meets ≤ 9 KB. `hygiene-rules.md` is **18,107 B**, which misses ≤ 16 KB. That figure comes after moving every helper-implemented detection text and all the measurement history to `docs/reference/lint-rules.md`, and condensing "Post-write verify". What remains is brain-doctor's own procedure:
> - the judgment-rule detections;
> - the broken-link phantom-target procedure;
> - the masking rule, every remediation (including the Jira wrap example and the code-in-braces edge cases);
> - "After repair — verify".
>
> Cutting further would strand the doctor on unshipped text, so the target is left unmet on purpose. The catalog is off the routine save path either way.

## 5. Eval gate

The suite exists (`evals/`, `docs/superpowers/specs/2026-09-13-eval-suite-design.md`). This release turns its two figures into pass criteria.

- **`load-digest`:** a `tool_count` grader, max 4, counted as `cost.py` does. The regex graders change as follows:
  - `digest-ran` accepts `brain load` as well as `brain digest`.
  - `activity` is unchanged. It matches the helper's `activity:` output line, which `load` still prints.
- **`save-basic`:** a `tool_count` grader, max 13.
  - `checked-index` and `checked-journal` are unchanged, because `save-finish` prints the same `check <file>: …` lines.
  - `saved-activity` is unchanged.
- **New case `graph-flag-trailing`:** a `load Demo` run with `LOGSEQ_BRAIN_PATH` set to a decoy graph, and the prompt naming `./graph`. It asserts:
  - the decoy's journal is byte-identical afterwards;
  - the real graph's journal gained the `(digest)` activity line;
  - no activity bullet contains `--graph`.
- **Fallback if the harness has no call-count grader.** If `claude plugin eval` has no `tool_count` grader kind, `tools/eval/summarize.py` fails the run when a `figures`-tagged case is over its target (§11, item 2).

> **Planning correction (independent review, 2026-09-25):** two changes.
> - **Five graders need a fix, not one.** Five graders (`one-status-call`, `lint-ran`, `digest-applied`, `search-ran` and `digest-ran`) and the README template reject a trailing `--graph`. They pass today only because the trailing call exits 2 and the model retries with the flag first. They are fixed in the same release as §1, and in any v0.11.1.
> - **`LOGSEQ_BRAIN_PATH` never reaches an eval run.** The `graph-flag-trailing` case therefore puts its decoy in a scaffold-written config file, if the scaffold's `HOME` is the run's (plan Task 0, Step 6). Otherwise the golden cases alone cover §1.
> - Making the two targets gating supersedes eval spec §7's "reported, never gating" for those two cases.
