# v0.11.0: Deterministic helper, fewer calls and exact figures (design)

**Date:** 2026-09-11
**Status:** approved (design)
**Theme:** move every mechanical step the skills currently perform by hand — measuring sections, computing the digest Map, truncating labels, fitting byte caps, scoping searches, detecting format errors — into one small POSIX `sh` + `awk` helper, so a save costs ~10–13 tool calls instead of ~29, and the figures and checks it produces are exact rather than approximately compliant with a 35 KB spec.

## Motivation

### Measured, not estimated

Everything below was measured on 2026-09-11 against the maintainer's live graph (`E:\Loqsec\ClaudeBrain`), Logseq's own parse cache for it, Logseq's page snapshots (`logseq/bak/`, `logseq/version-files/local/`), and the surviving Claude Code transcripts (2026-08-12 onward, all on v0.10.0). No paid eval runs were made; that was the maintainer's choice for this round.

**The graph grew 33 % in seven weeks**, to 60 pages (1,681 KB) and 91 journals (182 KB):

| Page | 2026-07-25 | 2026-09-11 | Notes |
|---|---|---|---|
| `Projects/Unicorn-Globus` | 108.9 KB | **184.4 KB** | Session Log 151.7 KB (82 %), 62 entries |
| `Projects/SELOS` | 59.8 KB | **168.9 KB** | Decisions 33 KB (32 entries) |
| `Tasks/CRMGM-1994` | 108.0 KB | **117.3 KB** | one flat 114.6 KB `## Notes` section |

31 done task pages hold 614 KB, 37 % of the graph. Rotation has never run: no `SessionArchive` page exists.

**Saves outnumber loads about 8 to 1.** Since v0.10.0 the journals' `## Activity` lines record 46 saves, 6 loads, 3 creations, 2 doctor runs and 1 backfill (154 saves vs 26 loads all-time). v0.10.0 cut the cost of a load by 99 %, but loads are the rare operation.

**What a save actually costs.** There are 17 brain-skill invocations in the surviving transcripts: 12 saves and 5 loads.

| | brain-save (n=12) | brain-load (n=5) |
|---|---|---|
| Tool calls, median (max) | **29** (42) | 12 |
| Context size when invoked, median (max) | **201k** (758k) | 66k |
| Instruction bytes read, median (max) | 17.8 KB (92.6 KB) | 21.4 KB |
| Graph bytes read, median | 34.4 KB | 15.2 KB |
| Output tokens, median | 25.6k | 16.4k |

A save runs at the end of a session, around 200k tokens of context, and every tool call re-sends that context. Cache reads are 66–88 % of a save's cost, so **the number of calls matters more than the bytes any one call returns.** Where the calls go:

- **About 6.5 measurement-only calls per save** (68 across the 12 saves). The digest's size was recomputed 3–4 times in 7 saves, and the section map up to 9 times in one save.
- **Line ranges don't bound bytes.** 69 `sed -n`/`head`/`tail` reads returned 200 KB, 49 % of all save graph bytes. Single ranges returned 20–28 KB.
- **Path resolution ran in 13 of 17 invocations**, though the graph path never changes.
- **Hand-retyped shell goes wrong.** One save built its section map with `/^## /`, which misses Logseq's `- ## ` headings; it came back empty. Two save greps used `\t` inside `grep -E`, which matches a literal `t`, and returned nothing.
- **Half of the 122 graph writes went through Bash or Python** (61 Bash, 59 Edit, 2 Write), so a save authors about 23 KB of tool input.

### What saves get wrong

Measured two ways, which agree:

1. **By the exact text saves wrote**, from the transcripts. 13 of 16 write groups wrote at least one finding. The 16 are the 12 brain-save windows, plus follow-up saves made without a Skill call, plus one load's activity line.
   - 71 links to task pages that have no file
   - 17 property keys outside the plugin's vocabulary (mostly de facto keys like `next-action::`)
   - 2 relative markdown links
   - 1 bare `#number`
2. **By page snapshots** (281 edit intervals, April–September): no new `{{ }}` or bare `#44` has been introduced since v0.10.0. **The compose-time self-check works wherever a rule exists.** Every remaining error falls outside the rules.

**Digests were often written wrong.** 66 distinct digests were judged at the first snapshot that carries them:

- **7 Map labels were paraphrased** instead of copying the heading or its 40-byte truncation. For example, `Session 08-12` for `Session 2026-08-12 — solved…`, and `Findings` for `Findings (2026-09-07)`. A label that isn't the heading can't be grepped back to its section. 4 of today's 21 digests carry one.
- **About 6 carry figures rounded up** (`108` for 107.5 KB, `38` for 37.5 KB). `digest.md` states twice that figures are truncated, "never rounded to nearest". Two are materially wrong: `Tasks/CRMGM-2040`'s Map claimed `Findings | 5 KB` for a 3.0 KB section.
- **6 overshot the 800 B cap and were then fixed in extra round trips.** `Tasks/CRMGM-1994` went 886 → 885 → 816 B within one minute.
- **Other defects:**
  - 2 current task digests have no Map at all (`CRMGM-2037`, `CRMGM-2046`).
  - 9 digests used `,` instead of the contract's ` · ` separator.
  - `open::` exceeds its 120 B cap on 4 current pages.
- **One refresh was skipped.** `Projects/Unicorn-Globus` was edited on 2026-09-07, which grew its Active Tasks section, without a digest refresh or an activity line. Its Map still says `Active Tasks | 20 KB` for a section that now measures 21.7 KB.

Many other "wrong figure" hits turned out to be snapshots taken between a save's Session Log append and its digest refresh. Those were discounted.

### What Logseq actually parses

Logseq's cache (`~/.logseq/graphs/logseq_local_…ClaudeBrain.transit`) decodes to the pages its parser created: **402 pages, 150 with a file, 237 without.**

| Group | Pages | Source |
|---|---|---|
| Orphans of already-fixed text | 103 | Logseq never garbage-collects. `25–`, `63`, `28`, `7)`, `0066CC`, `file:///c:/users/…` path chains, bare `CRMGM-1911`… Only a re-index clears them. |
| Property keys | 80 | `:property-pages/enabled? true` turns every `key::` into a page |
| Journal days with no file | 28 | Harmless |
| Missing task pages | 17 | Real `[[Tasks/…]]` links with no page behind them, including the current `focus::` task `CRMGM-2070` |
| **Live parse errors** | **8** | `-parity`, `-capable`, `-only`, `)`, `12`, `image`, and 2 relative `.md` links |

(The 237th file-less page is the `Tasks` namespace root, which is expected.)

The doctor's `bare-hash-tag` rule caught **0 of the 6 live tag phantoms.** Its regex assumes a tag is `#` + digits or hex, never preceded by a letter. Logseq's parser is broader: `C#-parity` → `-parity`, `C#)` → `)`, `PKCS#12` → `12`, CSS `#image` → `image`. The rule was written from a guess about the parser, and the parser disagrees. A prototype of the §4 rule caught 6 of 6 with no false positives, after two corrections the oracle forced: `#,` / `#"` / `#**` are not tags, and a `#` inside a markdown link label is not parsed.

### How loaded context gets used

The 5 real loads, and the sessions that followed each:

- **All 5 were entered by Jira task ID, not project name.** The matcher only globs `Projects___*.md`, so every load improvised. One read 40 KB of whole pages.
- **Of 10 requests that relied on project memory:** 1 was answered from the digest alone, 2 after escalation, and 6 needed things the brain never had (sessions that were never saved). In 1 the loaded context was stale, and in 1 it was ignored.
- **Ignored context produced a wrong premise.** The `CRMGM-1994` digest named Docker routing as the open blocker. Claude still drafted an IIS switch and told the user no firewall change was needed; the user corrected it.
- **A resolved blocker was presented as open**, from a stale `open::`-style digest line.
- **Coverage statements were stated in 3 of 5 loads and accurate in 1.** One claimed a page was "not read" 14 seconds after reading it whole.
- **Searches ignored their own scoping rules.** `search.md` says to keep only `pages/` and `journals/`; greps ran graph-wide instead. In one load 91 % of the grep output was `logseq/bak` and `version-files` noise. In another, `| head -20` cut off the real page and Claude concluded there was none.
- **Escalation skipped count-first and section scoping** (`escalation.md` rule 7). Two greps returned 14 KB and 16 KB, then re-read lines already held.

### The pattern

Saves and loads fail the same way: **the rules are right and precise, but compliance with them is not reliable.** Truncation versus rounding, label cutting, cap fitting, search scoping, count-first and coverage statements are each written down somewhere in ~150 KB of instructions, and each is missed in practice. Reading those instructions is itself a large part of the cost. More prose cannot fix a compliance problem. Moving the mechanics into a deterministic tool can.

### Reversing "no runtime code", deliberately

`CLAUDE.md` describes this plugin as "no build, no tests, no runtime code — Claude itself is the runtime". v0.10.0's design rejected `nbb-logseq` + `logseq-query` partly on that ground (§Motivation of `2026-07-25-v0.10.0-design.md`). This design reverses the rule, within a narrow boundary:

- **POSIX `sh` + `awk` only.** Nothing to install on any supported host: Git for Windows ships `bash` and GNU awk, macOS and Linux have `sh` and awk, and Cowork is a Linux sandbox. That is unlike a node/nbb runtime.
- **The script owns mechanics and derived content only.** Judgment — what to save, the Session Log entry, the digest's prose slots, decisions, which escalation level to use — stays with Claude.
- **It becomes the first code in the repo, so it gets the first tests** (§6).

### Decomposition

The findings span four sub-projects. This spec is **sub-project 1**, with the instruction diet (2) folded in wherever the script directly replaces prose.

| # | Sub-project | Status |
|---|---|---|
| 1 | Helper script + save/load/doctor/status wiring | **this spec** |
| 2 | Instruction diet | partly here (§3); the remainder follows once the script owns the mechanics |
| 3 | Graph policy: task-first entry (stub task pages, loading by Jira ID), size-based rotation, a property vocabulary and the `property-pages` setting, re-checking stale `open::` items | future spec |
| 4 | One-time cleanup of the maintainer's graph: the 8 live parse errors, a re-index, digest backfill | after release, driven by `brain lint --all` |

### Decisions made with the maintainer, 2026-09-11

| Question | Decision |
|---|---|
| Ship runtime code? | **Yes: POSIX `sh` + `awk`**, not Python and not prose-only |
| v0.11.0 coverage | **Save + load + doctor + status** as one toolkit |
| Does the script write? | **Only derived content.** Claude writes judgment content with Edit; the script writes only the Map line (`brain digest --apply`) and, as the one approved exception, the journey-log activity line (`brain activity`) |
| When the script can't run | **It is required.** One `sh` implementation. A PowerShell-only Windows host launches it through Git's `bash.exe`; with no Git at all, the skill stops with an install hint. No prose fallback path. |
| PowerShell twin (`brain.ps1`)? | **Rejected.** Two implementations of the same byte math and regexes would drift, and Windows PowerShell 5.1 reads BOM-less UTF-8 as ANSI, which miscounts Czech text (`č` = 2 bytes). |
| Structure | **One dispatcher + one awk file per concern** (not a single file, not one script per workflow) |

## 1. Command surface

Every command replaces a specific step the skills currently perform by hand.

### 1.1 Read-only commands

| Command | Output | Replaces |
|---|---|---|
| `brain digest <page>` | The whole property block and the whole `## Digest` span, however long, plus `map: ok \| stale (<label> <claimed>→<measured>) \| missing`, `drift: <N> days` (`digest-updated::` vs `last-updated::`), and the staleness level. With no digest: the property block, `digest: missing`, and the section table. | brain-load step 2 (the `limit 20` read, the Map-present re-read, drift arithmetic), step 6 (staleness) and the fallback's sizing |
| `brain journal <Projects/X\|Tasks/X> [--date yyyy-MM-dd]` | That page's mentions in the day's journal, shrunk to fit ~2 KB (whole-file search; drop the oldest match until under the target, never zero), plus a coverage line | brain-load step 4 |
| `brain sections <page> [--baseline <file…>]` | One row per `## ` section: `line end bytes entries heading`, plus the page total. As a side effect, records a **baseline copy** of the page, and of every extra file named after `--baseline` (a save names the Index and today's journal), in the temp directory (§2.5), never in the graph. A named file that does not exist yet gets an empty baseline, so everything later written to it counts as new. | "Measure before you read", the heading grep, span arithmetic |
| `brain read <page> "<section>" [--max <bytes>]` | The section if it fits under the cap (default 8 KB); otherwise a refusal stating its size. Coverage line. | Escalation level 4 |
| `brain tail <page> "<section>" [--entries N] [--max <bytes>]` | The newest N dated entries, scoped to that section, dropping the oldest until under `--max`, never zero. With no dated entries, the section's last bytes up to `--max`, stated in bytes. Coverage line: `coverage: 1 of 12 entries, 2.8 KB of 29.6 KB`. | The "Reading a section's tail" recipe in `section-locator.md` |
| `brain search <term> [--page P] [--section S] [--context N]` | **Counts first**, over `pages/` and `journals/` only. When there are **≤ 20 hits and ≤ 4 KB of output**: each hit with its page and section label, done-task and archive pages marked. Over that: per-page and per-section counts only. With `--context N` (escalation level 3), the ±N-line windows are merged and capped at **8 KB total** (escalation rule 7); a request over the cap returns counts plus the byte cost instead. Always ends with `coverage: showed <n> of <m> hits`. | `brain-load/references/search.md`, escalation levels 2–3 |
| `brain check <file…>` | Lint of only the lines added since each file's baseline, split into **new** findings and a count of **pre-existing** ones. Digest checks for digest-bearing pages. Exit 1 on any new error-tier finding (§4.3). A file with no baseline (or one older than 12 h) is linted whole, its findings are labeled `(no baseline — may be pre-existing)`, and they **never set exit 1**. | brain-save step 11 (post-write verify) |
| `brain lint [--all \| <file…>]` | Every rule (§4) as `file:line rule snippet`, plus per-rule counts | The detection half of brain-doctor's scan |
| `brain status` | One tab-separated row per project and task page: `type status last-updated digest-updated drift staleness focus next open`, including pages with no readable properties (flagged, never dropped) | brain-status Dashboard steps 1–5 and 8, and the Analytics task counts |

### 1.2 Writing commands

| Command | What it writes |
|---|---|
| `brain digest --apply <page>` | Recomputes the Map from the file (§1.3) and **replaces only the Map line**, or inserts it as the last bullet of `## Digest` when the section has none (e.g. `Tasks/CRMGM-2037`). The `## Digest` section itself must already exist: Claude creates it, prose included, with Edit. Re-measures the file until the `page` figure is stable. Then runs the digest checks (800 B section cap, 120 B property caps, separator, Map present) and the lint over lines added since the baseline. Prints what needs judgment rather than fixing it: `digest prose over cap by 70 B`, `open:: is 154 B (cap 120)`. The same call serves brain-save's Refresh, rotation's Remap, brain-doctor's Remap and brain-init's new-page scaffold. |
| `brain activity "<line>"` | Appends `HH:mm <line>` under today's journal's `## Activity`, creating the journal file or the heading exactly as `journey-log.md` specifies. The one script write of text Claude composes, approved because placing it (heading creation, Logseq's reformatted heading forms, unique anchoring) is pure mechanics. No-op when the config sets `journeyLog: false`. |

### 1.3 The Map is computed exactly as `digest.md` specifies

`digest --apply` implements the existing contract, not a new one. The Map written by v0.11.0 is byte-for-byte what a correct v0.10.0 hand computation would produce, so a device still on v0.10.0 reads it correctly:

- Every `## ` section except `## Digest`, measured as the lines after its heading up to the next heading.
- Sections at or above 1 KB, largest first.
- Figures in KiB, **truncated**. Exact bytes below 1 KB.
- `Session Log` and `Decisions` carry their dated-entry count, using the widened pattern and the child-bullet cross-check. The count is omitted rather than published as a known floor.
- Labels are the exact heading, or its 40-byte cut with `…`, cut at a UTF-8 character boundary. Colliding cuts are widened.
- Items are joined with ` · `, and each label is joined to its figure with ` | `.
- A reconciling `+N smaller sections, X KB` clause, then the `Archive` pointer when present, then `page`.
- Cap fitting reserves room for the trailing clauses before accepting a candidate section.

Legacy `,` separators are normalized the next time a save applies the digest.

### 1.4 Conventions

- Plain-text output, one fact per line. Every command that returns graph content ends with a `coverage:` line.
- Exit codes: **0** = clean, **1** = findings, **2** = usage or environment error, with a one-line reason on stderr.
- Pages are named `Projects/X` or `Tasks/X` (the `___` filename form and a path are also accepted).

### 1.5 Expected call counts

| Operation | v0.10.0 median | v0.11.0 shape |
|---|---|---|
| Digest load | 12 | `brain digest`, `brain journal`, `brain activity` → **3** |
| Save | 29 | `brain sections <page> --baseline <Index> <journal>` → 1–3 targeted reads (`brain read`/`tail`) → 3–5 Edits (Session Log, Current Plan, digest prose + properties, Index one-liner, journal `## Sessions`) → `brain digest --apply` → `brain check` → `brain activity` → **~10–13** |

## 2. Runtime and invocation

### 2.1 Layout

```
skills/_shared/bin/brain        POSIX sh dispatcher (~150 lines): argument parsing,
                                graph resolution, LC_ALL=C, routing
skills/_shared/lib/*.awk        one concern per file — initially sections, map, lint,
                                status, journal
skills/_shared/lib/search.sh    scoped search; uses rg when present, grep -r otherwise,
                                identical output either way
skills/_shared/run-brain.md     ~10 lines: how a skill invokes the script (§2.2)
```

The `.plugin` archive (`git archive … skills …`) already packages `bin/` and `lib/`. The script is always invoked as `sh <path>/brain`, so a lost executable bit (zip archives, Windows checkouts) never matters.

### 2.2 Invocation from a skill

The script lives at `<skill-base>/../_shared/bin/brain`: the same relative-path convention the skills already use for `skills/_shared/*.md`, so it resolves on every host that loads the skills.

1. **Bash-capable host** (Claude Code, Cowork, Gemini or Copilot CLI on Unix, or Windows with Git Bash): `sh <path>/brain <cmd> …`
2. **PowerShell-only host on Windows:** `& "<git-root>\bin\bash.exe" <path>/brain <cmd> …`, where `<git-root>` is two levels above `(Get-Command git).Source`. Installing from the skillsmith marketplace is a git clone, and the standard Git for Windows install ships `bin\bash.exe` and GNU awk. Verified on the maintainer's machine: GNU Awk 5.4.0.
3. **Neither works:** stop with `logseq-brain needs Git for Windows (Git Bash) — https://git-scm.com/download/win`.

### 2.3 Graph resolution

The script resolves the graph as `--graph <dir>` → `LOGSEQ_BRAIN_PATH` → `graphPath` in the config file (`$APPDATA/logseq-brain/config.json` on Windows; `$XDG_CONFIG_HOME/logseq-brain/config.json` or `~/.config/logseq-brain/config.json` otherwise). This is the same order as `path-resolution.md` steps 2–3. It converts Windows paths itself (`E:\Loqsec\…` → `/e/Loqsec/…`, using `cygpath` when present). When nothing resolves, it exits 2 with `graph not resolved`, and the skill runs the parts that need a human or a host API: asking and persisting (step 5), the legacy migration (step 4), and Cowork's `request_cowork_directory`. The skill then retries with `--graph`. Cowork always passes `--graph`. `brain activity` reads the `journeyLog` toggle from the same config file.

### 2.4 Portability rules

Each rule exists because breaking it corrupts a figure:

- **`LC_ALL=C` for everything**, so lengths are bytes, not characters. Verified: `printf 'č' | LC_ALL=C wc -c` → 2.
- **POSIX awk only.** Linux distributions often ship mawk, macOS ships BWK awk, Git Bash ships gawk. Therefore:
  - no `gensub`, no three-argument `match`, no `strftime`/`systime` (dates come from `date`)
  - no `{n,m}` interval expressions, which older mawk lacks
  - no `length(array)` reliance
- **Tolerate** `\r`, a missing final newline (Logseq writes none), both `- ## X` and `## X` headings, and tab or space indentation. Byte figures always count the file's real bytes, `\r` included.
- **Never match headings inside fenced code blocks.**

### 2.5 Write safety

This applies to `digest --apply` and `activity`, the only commands that write:

1. Read the target and record its size and mtime.
2. Build the new content in `$TMPDIR`. Never write temp files into the graph, because Logseq and Sync watch that folder.
3. **Verify the change touches exactly the Map line** (replaced, or inserted as the last bullet of `## Digest` when absent), **or exactly one appended activity bullet** (plus the `## Activity` heading, or the file itself, when those had to be created). Anything else: abort, write nothing, exit 2.
4. Re-check size and mtime. If either changed, abort with `changed during apply — rerun`.
5. Commit with an in-place `cat "$tmp" > "$target"`: a single write event, the same shape as an Edit.

The script never deletes, and never writes outside `pages/` and `journals/`. Baselines for `brain check` live in `$TMPDIR/logseq-brain/<graph-hash>/` and expire after 12 hours.

## 4. The lint engine

### 4.1 Rules

Detection is modeled on what Logseq OG actually parses, validated against its cache (§4.4). Rule names stay as they are, so doctor reports stay familiar.

| Rule | Detection in v0.11.0 | Change |
|---|---|---|
| `bare-hash-tag` | `#` followed by a character that can start a tag, **regardless of the preceding character**, outside masked spans (§4.2). Sub-classified `number`, `hex`, `after-word`, `word`, `punct` in the output. **Oracle-verified:** `-`, `)`, digits and letters start a tag; `,`, `"` and `*` do not; neither do whitespace, `#`, `[` or a backtick. **Not yet verified:** `.`, `;`, `:`, `!`, `?` and `'`. They are assumed not to start a tag, by analogy with `,`, and must be confirmed by the fixture-graph check (§4.4) before release. | **Redefined.** Still catches `#44` and `#0066CC`; now also `C#-parity`, `C#)`, `PKCS#12` and CSS `#image`. |
| `code-in-braces` | `{{` not opening a known Logseq macro | Unchanged meaning |
| `unnamespaced-link` | `[[ABC-123]]`: any uppercase prefix, not only `CRMGM\|GLOPRICE` | Generalized |
| `file-link` | `[[file:` | Unchanged |
| `relative-link` | Markdown link whose target is not a URL, `mailto:`, an anchor or `assets/` | **New.** `[x.md](docs/x.md)` creates a page named after the target. |
| `jira-markup` | `h1.`–`h6.`, `{code}`, `{noformat}`, `\|\|` table rows, `[~user]` outside fenced blocks | Unchanged meaning |
| `malformed-property` | `key: value` inside a page-top property block | Unchanged |
| `broken-link` | `[[Projects/…]]` / `[[Tasks/…]]` with no page file | **Now mechanical.** The most common save error: 71 links across 13 of 16 write groups. |
| `new-property-key` | A `key::` used nowhere else in the graph | **New.** Each new key becomes an empty Logseq page while `:property-pages/enabled?` is on. |
| `map-label` | A Map label that is neither the exact heading nor its 40 B cut | **New.** Breaks section lookup by label. |
| `missing-digest`, `stale-digest`, `stale-map`, `oversized-digest` | Via the §1.3 computation. `oversized-digest` also covers `focus::`/`next::`/`open::` over 120 B, a missing Map, and a wrong separator. | Same rules, exact figures |
| `description-link`, `duplicate-entry`, `structural-integrity` | Unchanged prose detection | Need whole-graph judgment; brain-doctor walks them with the user |

### 4.2 Masking

Before any rule runs on a line, these spans are blanked with column positions preserved:

- fenced code blocks (stateful across lines)
- inline code (single or multiple backticks)
- whole markdown links `[label](target)`, label included, because `[#65](url)` does not create a page
- bare URLs
- `#[[…]]` tag-links
- heading markers

POSIX ERE has no non-greedy matching, so masking is a small character scanner, not a regex.

### 4.3 Tiers in `brain check`

- **error** (exit 1; fix before the save finishes): every mechanical rule, plus the digest caps and Map rules.
- **warn** (printed, exit 0): `broken-link` and `new-property-key`. Whether saves should create stub task pages, and which keys form the vocabulary, is sub-project 3's call. Until then a save tells the user `new link to missing page Tasks/CRMGM-2070` instead of silently creating a phantom page, without blocking.

### 4.4 Oracle validation

The transit-cache decoder written for this investigation becomes a maintainer tool, `tools/oracle/`:

- It is Python and dev-only, and is never shipped: the `.plugin` archive packages only `.claude-plugin`, `skills` and `README.md`.
- It lists every page Logseq created that has no file, and diffs that list against `brain lint --all`.
- **Any change to detection must pass it against a real graph:** every live parse-error page caught, no false positives. The current `bare-hash-tag` rule never had that check, and it caught 0 of 6.
- It cannot run in CI because it needs a Logseq desktop cache. CI relies on the fixtures in §6 instead.
- **The fixtures' expectations are themselves ground-truthed.** Before release, the lint fixtures are opened as a scratch graph in Logseq desktop, and the oracle is run against that graph's cache. Every fixture's expected findings must equal the pages Logseq actually created. This settles the unverified tag characters in §4.1, and any future parser question, by measurement.

**Known limit:** Logseq's parser surely has edge cases this graph does not show. The oracle re-run is how new ones get found, instead of rules being guessed again.

## 5. Failure handling

The rule throughout: the script never guesses and never silently truncates. It either does the exact thing, or exits 2 with one line telling the skill what to do next.

| Situation | Behavior |
|---|---|
| Script can't run | The skill stops with the Git for Windows message (§2.2) |
| Graph not resolved | Exit 2 `graph not resolved`. The skill asks, persists, and retries with `--graph`. |
| Page not found | Exit 2 plus up to 5 near matches by substring, so fuzzy matching costs no extra call |
| No `## Digest` | `brain digest` prints the property block, `digest: missing` and the section table. The fallback load proceeds and offers a build, as today. |
| Headings inside fences; duplicate headings | Fenced headings are ignored. Duplicates are told apart by line number. Colliding label cuts are widened (§1.3). |
| Digest prose leaves no room for the Map under 800 B | Write the smallest correct Map (`+N more`, residual, `page`), then exit 1 with `digest prose over cap by <n> B`. Claude shortens the prose with Edit and reruns. The Map line is never wrong, even when the prose is too long. |
| File changed during `digest --apply` | Exit 2 `changed during apply — rerun`, nothing written |
| No baseline, or one older than 12 h | `brain check` lints the whole file, labels findings `(no baseline — may be pre-existing)`, and does not set exit 1 for them, so it never blames the save for another device's edits |
| `digest --apply` on a page that carries no digest by scope | Journals, `Index.md`, `Meta.md`, `Decisions.md`, session-archive and auxiliary pages (per `digest.md`'s scope rule): exit 2 `not a digest-bearing page` |
| A label cut would land inside a multi-byte character | Back off to the character boundary (a byte table built under `LC_ALL=C`) |
| `journeyLog: false` | `brain activity` prints `journey log disabled` and exits 0 |
| Today's journal missing, or missing `## Activity` | Created or inserted exactly as `journey-log.md` specifies, tolerating Logseq's reformatted heading forms |
| Search output would be large | Capped at ~4 KB, then per-page and per-section counts, then `coverage: showed <n> of <m> hits`. Never a silent `\| head`. |
| Backups and conflict copies | `logseq/` (including `bak/` and `version-files/`) and `.recycle/` are never searched or linted |

## 6. Testing

### 6.1 Golden-file suite

`tests/run.sh` (POSIX sh) runs every case in `tests/cases/<name>/`. A case holds:

- a minimal fixture graph (`pages/`, `journals/`, optionally a config file)
- `cmd`: the arguments
- `expected.out` and `expected.exit`

The harness runs `brain --graph <fixture> <cmd>` and diffs the output. For `digest --apply` and `activity`, it also diffs the resulting file bytes and asserts the one-line-change property (§2.5).

The fixtures are the real edge cases found in this investigation, minimized:

- **File shapes:** `- ## ` vs `## ` headings; no final newline; CRLF; tab indentation.
- **Sections and entries:**
  - `### yyyy-mm-dd` dated entries; a Session Log that is not the last section; a section with zero dated entries
  - a Czech heading longer than 40 B (UTF-8 cut); two headings whose cuts collide
  - a task page whose property block runs past 20 lines
- **Lint:** `C#-parity`, `C#)`, `PKCS#12`, `#image`, `[#65](url)`, `` `#25`–`#28` ``, relative `.md` links, Jira markup inside and outside fences.
- **Digests:** prose over the cap; a Map with `,` separators; a paraphrased Map label; `open::` over 120 B.
- **Journals:** no `## Sessions` heading; 4 mentions of one project in a day (shrink-to-fit); an empty `## Activity`; a missing journal.

### 6.2 CI

`.github/workflows/test.yml` is the repo's first workflow. It runs `sh tests/run.sh` on **ubuntu-latest** (mawk), **macos-latest** (BWK awk) and **windows-latest** (Git Bash, gawk), so all three awk families are exercised on every PR.

### 6.3 Maintainer tools (`tools/`, Python, dev-only, never shipped)

This adopts two of the investigation's throwaway scripts, cleaned up:

- `tools/oracle/`: the transit decoder and the diff against `brain lint --all` (§4.4). Run it before any release that touches detection.
- `tools/measure/`: the transcript cost analysis (tool calls, bytes, instruction share per brain-skill window) and the snapshot Map-accuracy check. It turns "did this release work?" into a rerun instead of an estimate.

### 6.4 Manual round-trip

The `CONTRIBUTING.md` checklist is updated. The token check (step 8) now counts tool calls per operation, not only bytes. New steps: run the suite; before release, run the oracle against a live graph and against the lint fixtures opened as a scratch graph in Logseq desktop (§4.4).
