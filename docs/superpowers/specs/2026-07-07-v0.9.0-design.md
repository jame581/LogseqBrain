# v0.9.0 — Prevention, lifecycle, findability (design)

**Date:** 2026-07-07
**Status:** approved (design)
**Theme:** make prevention mechanical instead of instructional, give task pages a lifecycle, keep the Index fresh, and fix the rules that cry wolf.

## Motivation

A brain-doctor scan on 2026-07-07 — two weeks after the v0.8.0 cleanup — found the same graph re-polluted:

| Finding | Count | Root cause |
|---|---|---|
| `{{ }}` broken macros | 89, all in one task page | Czech **Jira comment drafts saved verbatim** — Jira wiki markup legitimately uses `{{monospace}}`, no compose rule covered it |
| Bare `#N` phantom tags | 48 across 5 files | GitHub issue numbers / cleanup-item numbers slipped through brain-save's **instructions-only** self-check |
| `duplicate-entry` rule output | ~100% false positives | normalization strips `HH:mm` and counts repeating `skills-used::` / `related-tickets::` property lines as duplicates |

Every violation postdated v0.8.0 (2026-06-25 through 2026-06-30). Conclusion: compose-time *instructions* demonstrably do not survive contact with real sessions. The check must grep reality.

Two structural pressures also surfaced: 33 `Tasks___*` pages accumulate with no lifecycle (40–80 KB each), and `Projects___Unicorn-Globus.md` is 96 KB with an unbounded Session Log. `Index.md` one-liners rot (it still said "v0.7.0 shipped" when v0.8.0 was three weeks old), and the cross-project `Decisions.md` is empty while real decisions sit buried in session-log prose.

Decisions in this design were made with the maintainer on 2026-07-07/08 (recorded in the brain: `Projects/LogseqBrain` → Decisions, 2026-07-07).

## 1. Prevention hardening

### 1.1 New hygiene rule: `jira-markup`

Added to `skills/_shared/hygiene-rules.md`:

- **severity:** breaks-render · **enforced-at:** compose, scan · **auto-fixable:** report
- **Compose (brain-save):** a Jira comment draft (signals: the user calls it a Jira comment; or the text contains `h[1-6].` headings, `{code}`/`{noformat}`, `[~mentions]`, `{{monospace}}`) is stored **verbatim inside a fenced code block**: one pointer bullet above it (date, ticket, one-line gist), the fence as its child bullet. Logseq does not parse fenced content — no phantom pages, no broken macros, and the draft stays copy-pasteable exactly as posted.
  - *Alternatives rejected:* converting Jira markup to Logseq format on save (translation bugs, draft no longer round-trips to Jira); storing only a pointer (loses the draft text).
- **Scan (brain-doctor):** Jira residue **outside** a fence — `h[1-6]\.` at bullet start, `{code}`, `{noformat}`, `[~…]` — is **report-tier**: deciding where a draft begins and ends needs judgment, so brain-doctor suggests wrapping and the user confirms. Raw `{{x}}` outside fences remains covered by the existing auto-fixable `code-in-braces`.
- `skills/_shared/logseq-format.md` gains the compose invariant: **foreign markup (Jira wiki, etc.) never goes raw into bullets — fence it.**

### 1.2 Mechanical post-write verify in brain-save

New step after all writes in a save (project page, journal, Index, Meta):

1. One Bash call runs the auto-fixable detections (`code-in-braces`, `bare-hash-tag`, `unnamespaced-link`, `file-link`) **plus per-file backtick parity**, scoped to **only the files written in this save**.
2. Any hit → fix using the catalog's masking-aware remediation → re-run the detection to confirm zero.

The in-memory compose self-check (v0.8.0 step 5) stays — it is free and catches most issues before they land — but the grep is the safety net that checks what actually reached disk. It would have caught both June regressions by construction.

The verify procedure lives in `hygiene-rules.md` (extending its existing "After repair — verify" section) so `brain-init` can reuse it. Journey-log one-liners written by other skills keep compose-check only (single short line, low risk, not worth a Bash call per load).

## 2. Task lifecycle

### 2.1 `status::` on task pages

- Task pages carry `status:: active | blocked | done` in the page-top property block. The rest of the task-page shape stays deliberately loose (no fixed template).
- **brain-save**, when touching a task page: seeds `status:: active` if the property is missing; when the session content signals completion ("merged", "deployed", "closed", "hotovo"), it **suggests** `done` — consistent with the plugin's suggestion-only rule, it never writes a status the user didn't confirm.
- **brain-status:** dashboard groups tasks by status; `done` tasks collapse to a single count line.
- **brain-load** brief mode: skips `done` task pages.
- **`skills/_shared/staleness.md`:** `done` tasks are exempt from staleness flags (finished work is not "stale").

### 2.2 One-time guided backfill

`structural-integrity` (brain-doctor) gains the check *task page missing `status::`* with a **guided batch remediation**: list every task page with its most recent session date, propose `done` for all except the visibly active ones (a session entry within the last 30 days, or the task is listed in a project page's Active Tasks / Current Plan section), apply on one confirmation. Runs once against the maintainer's graph (33 task pages) as part of release validation. Report-tier as always — never auto-written.

### 2.3 Session-log rotation for large project pages

- **Trigger (suggestion-only):** after appending a session entry, if the project page exceeds **64 KB or 40 session entries** (defaults, judgment allowed near the line), brain-save suggests rotation.
- **Action on confirmation:** move Session Log entries older than **90 days** to `pages/Projects___<Name>___SessionArchive.md` (created on first rotation with page-top props `type:: session-archive`, `created::`, plus a link back to the project page). The main page's Session Log keeps a first bullet: `Older entries: [[Projects/<Name>/SessionArchive]]`.
- One confirmed batch move, executed as surgical edits (cut from main page, append to archive). Archive pages are excluded from brain-load brief mode and staleness checks; cross-graph search still reaches them.
- *Alternative rejected:* lossy rollup summaries (original wording matters for a memory system).

## 3. Findability

### 3.1 Index auto-refresh on save

brain-save's step 9 ("update Index.md if status changed") becomes concrete and unconditional: every save rewrites the saved project's one-liner **parenthetical** in `pages/Index.md`. Format: stable descriptor stays untouched; the parenthetical becomes *(latest version or milestone — current focus)*. This is a surgical single-line Edit and permanently kills Index rot.

### 3.2 Decision prompting (forward-only)

While composing the session summary, brain-save scans its own composed text for decision-shaped statements ("decided", "chose X over Y", "went with", "rozhodnuto", "superseded") and asks: *"These N statements look like decisions — record them in Decisions?"* Approved ones are written as proper decision entries (`context::` / `alternatives::` / `rationale::` / `status::`) to the project page's Decisions section, and cross-project ones also to `pages/Decisions.md` per the existing rule in `references/decisions.md`.

*Rejected for v0.9.0:* retro-mining existing Session Logs across 49 pages (large token spend, many confirmations about stale decisions). Can be revisited if forward-only proves valuable.

## 4. Rule quality

- **`duplicate-entry`:** normalization now (a) **excludes property lines** (`^[a-z][a-z0-9-]*:: `) — repeating `skills-used::` across sessions is expected, and (b) **keeps the `HH:mm` prefix** in the journal-bullet comparison key — two saves of the same project in one day are two events, not a duplicate. Flag only exact normalized repeats.
- **`bare-hash-tag`:** detection and remediation adopt the punctuation-aware pattern proven in the 2026-07-07 repair — effectively a lookbehind excluding ``[\w/&`#\]]`` — so `(#1)`, `#2–#5`, and other punctuation-adjacent tags are caught. Masking rules (backticks, `{{ }}`, `#[[…]]`) unchanged.
- **`structural-integrity`:** adds the task-page `status::` check (feeds §2.2). The known finding `Projects___Unicorn-Globus___Tasks.md` missing `status::`/`created::` is fixed during release validation.

## Validation

No runtime/tests — validate against the maintainer's real graph per `CONTRIBUTING.md`:

1. Save a session containing a Jira draft → draft lands fenced; post-write verify grep reports clean.
2. Deliberately compose a violation (bare `#12`) → post-write verify catches and fixes it.
3. brain-doctor scan → `jira-markup` reports unfenced residue; `duplicate-entry` reports zero false positives on the known property-line repeats.
4. Guided backfill on the 33 task pages → statuses seeded, brain-status groups correctly, brief load skips done tasks.
5. Rotation suggestion fires on `Projects___Unicorn-Globus.md` (96 KB) → archive page created, main page lean, link intact.
6. A normal save → Index one-liner refreshed; decision prompt fires only when decision-shaped text exists.

## Not in scope

Storage abstraction, Logseq DB plugin API, headless CLI sync, Sync conflict resolution, packaging refinements — all still gated on Logseq's own roadmap (unchanged from v0.8.0). Retro-mining decisions from historical session logs — deferred (see §3.2).
