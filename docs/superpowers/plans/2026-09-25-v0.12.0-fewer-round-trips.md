# v0.12.0 Fewer Round Trips Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring a digest load from 11 tool calls to ≤ 4 (shape: 2) and a save from 27 to ≤ 13 (shape: 7). Fix the trailing `--graph` bug, which can write to the wrong graph. Make the routine load and save read nothing but their SKILL.md. The eval suite proves the call targets as pass criteria.

**Architecture:** Nothing new at the base. The dispatcher gains a flag pre-pass and three composite commands (`load`, `save-begin`, `save-finish`). Each is a shell function calling the existing `cmd_*` functions in one process. `save-finish` gains two writes under the existing verified single-change commit (`commit_write` + `onechange.awk`):
- the journal `## Sessions` bullet;
- the parenthetical of the page's `pages/Index.md` one-liner.

Before its first write, `save-finish` validates everything it can: the text, the digest caps, and whether the Map is computable. A refusal therefore leaves the graph untouched, and the same command can simply be rerun. Skill prose is rewritten around the composites. Developer-only contract text that no shipped skill needs moves to `docs/reference/`, which is not shipped.

**Tech Stack:** unchanged from v0.11.0: POSIX `sh`, POSIX `awk`, base coreutils. Python 3 only in dev-only `tools/`. The eval suite runs in WSL2 as the `logseq-eval` user.

**Spec:** `docs/superpowers/specs/2026-09-25-v0.12.0-design.md`. Maintainer decisions D1–D5 were all accepted as recommended on 2026-09-25. The plan was revised after two independent reviews the same day (see "Review log" at the end). The spec carries a "Planning correction (independent review, 2026-09-25)" annotation for every place this plan departs from it.

## Global Constraints

Every task's requirements implicitly include this section.

- **Carried over from the v0.11.0 plan's Global Constraints, unchanged:**
  - Logseq OG only.
  - POSIX sh/awk only: no `gensub`, no three-argument `match`, no `strftime`/`systime`/`mktime`, no `length(array)`, no `{n,m}` intervals.
  - `LC_ALL=C`.
  - KB means KiB, truncated.
  - `-v BINMODE=3` on every awk.
  - Never `echo` user text (use `printf '%s'`).
  - Paths guarded.
  - Exit codes 0 / 1 / 2.
  - Graph-relative output (except `info`'s `graph:` line).
  - Invocation always through `sh`.
- **Regexes and user text never go through `awk -v` unescaped.** `-v` applies string-escape processing:
  - gawk and BWK awk turn `\[` into `[`. On gawk that is a fatal "Unmatched [". BWK awk dies with "nonterminated character class". Worse, a `\.` quietly becomes "any byte".
  - mawk keeps the backslash, so a local mawk run hides all of this.
  - Therefore:
    - every regex handed to `-v` has its backslashes doubled (`'\\[\\['`);
    - page names and all user text go to awk through `ENVIRON`, as `activity.awk` already does with `BRAIN_BULLET`;
    - every task that adds a regex or a name to an awk call runs its new cases under **mawk, gawk and original-awk** before committing. CI runs all three, plus macOS BWK awk and Windows gawk.
- **The helper writes exactly four kinds of line, all through `commit_write`:**
  1. the Map line (`digest --apply`);
  2. one activity bullet (`activity`);
  3. one `## Sessions` bullet (`save-finish --summary`, new);
  4. the one-liner's parenthetical in `pages/Index.md` (`save-finish --index`, new).

  Plus, for kinds 2 and 3 only, the heading or the journal file when it must be created. Nothing else, ever. Every new write kind gets a refusal test and runs under the harness's write-safety assertion.
- **Claude-composed text the helper writes is validated before it is written.** `--summary` and `--index` text is refused (exit 1, nothing written anywhere) when it:
  - contains a newline or CR;
  - has an error-tier lint finding;
  - for `--index`, has unbalanced parentheses.

  Logseq parses a file as soon as it changes and never deletes a page it created, so a phantom page must be stopped before the write, not after.
- **Composite-local variables are prefixed** (`_ld_*` in `load`, `_sb_*` in `save-begin`, `_sf_*` in `save-finish`). The `cmd_*` functions share un-prefixed globals: `_rel`, `_t`, `_sum`, `_tmp`, `_rc`, `_f`, `_mode`, `_n`, `PAGE_REL`, `PAGE_NAME`, `ARCH`. `digest_lint` alone resets `PAGE_REL`/`PAGE_NAME`/`ARCH` for every page it lints. Capture everything a composite needs later **before** calling into them.
- **No `VAR=value fn` prefix assignments inside composites.** macOS `/bin/sh` (bash 3.2 in POSIX mode) keeps such variables set after the function returns. Set and unset them explicitly instead.
- **A sub-command that can `exit` is run in a subshell** when the composite must continue past its failure: `( cmd_read_tail … )`, with the rc mapped afterwards. The EXIT trap does not run in `( )` subshells under dash or bash, so `RUN_DIR` survives (verified in review).
- **Existing commands keep their exact output.** brain-doctor, brain-status, rotation and recovery paths still call them. The existing 78 golden cases stay green after every task. The one sanctioned change is Task 9's hint lines, and it is reviewed as a diff.
- **Composite output is concatenated sub-command output,** each block headed by a `== <name>` line. No figure or coverage line is reformatted.
- **Never `git add -A`.** Always stage explicit paths.
- **Commit trailer** on every commit:
  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: <the implementing session's URL>
  ```
- **Branch:** `v0.12.0`, per repo convention. Create it from `main` after merging the branch that carries this plan and the spec (`claude/vigilant-bardeen-07hk40`).
  - Every commit is conventional **with a scope**: `fix(brain):`, `feat(brain):`, `test(harness):`, `docs(brain-save):`, `test(evals):`, `docs(readme):`, `chore(release):`.
- **The eval suite and anything touching the live graph are maintainer steps** (WSL2, plan usage, the maintainer's machine). Tasks mark them **[maintainer]**. An agent prepares the change and the exact commands, and does not claim a result it did not see.

## Deliberate refinements of the spec

Each was decided while planning or in review. They are recorded here so that no implementer "fixes" them back to the spec's wording. The spec's planning-correction annotation lists the same items.

1. **`--` is consumed, not passed through.** `brain search -- --graph` reaches `cmd_search` as the single argument `--graph`.
2. **An empty `--graph` is an error.** `--graph ""` and `--graph=` exit 2 with `--graph needs a directory`. Today `resolve_graph` skips an empty value and silently falls through to the environment: the same wrong-graph class of bug, triggered by a model passing an unset variable.
3. **`save-finish` order:**
   1. validate (manifest, text, digest caps, a dry-run Map on every digest-bearing manifest page);
   2. `--summary` write;
   3. `--index` write;
   4. Map writes;
   5. one check over the save set;
   6. the activity line.

   Nothing is written unless step 1 passes. The page is never modified by the helper before the model's last Edit is validated, so a cap-fix Edit never meets a "file modified since read" error.
4. **The activity line is deferred while the save has a new error-tier finding.** `save-finish` then prints `activity: deferred — fix the errors above, then run: brain check <files> && brain activity 'saved [[…]]'`. Warn-tier findings do not defer it, and do not make the exit code 1 (check exits 1 on errors only).
5. **`save-finish` runs one check over the whole set, with digest lint on.** It never runs `digest --apply`'s own inner page check. `cmd_digest_apply` is split for this (Task 4). The `digest_report` block is still printed, because it carries the `over:` lines. Digest findings can therefore appear twice, once in the report and once in the check. That is accepted and documented.
6. **One manifest per page:** `$STATE_DIR/save.<page key>.lst`, written by `save-begin`.
   - A multi-project save runs `save-begin` → Edits → `save-finish` **per page, in sequence**. The shared Index and journal baselines are retaken by each `save-begin`, so the pages must not interleave.
   - `save-begin` may be rerun before the first Edit, for example to add `--also` once the need is known at compose time.
   - `save-finish` exits 2 when there is no manifest, or the manifest is older than 12 h (the baseline expiry). The message: `no save-begin for <page> in the last 12 h — run brain save-begin first`.
7. **`save-finish` Remaps every digest-bearing page in the manifest,** not only the main one. A task page whose `status::` changed is passed as `--also pages/Tasks___<ID>.md`, and its Map is refreshed and checked.
8. **Manifest files that are absent on disk and had an empty baseline are skipped by the check,** with `check <f>: not written (absent)`. `cmd_check` would otherwise die with `no such file`, after the Map write and before the activity line. That happens with no `--summary` and no journal yet, with no `pages/Index.md`, or with an `--also` file that was never created.
9. **The Sessions append is idempotent.** A bullet identical to one already under `## Sessions` is not written again, and `sessions: unchanged` is printed. This makes a rerun after any late failure safe.
10. **The Index one-liner applies to project pages only.** On a task page, `--index` prints `index: not applicable (task page)`, and the skill does not pass it. Lookup is restricted to the `## Projects` section, to lines whose **first** `[[…]]` link is the page. The parenthetical replaced is the last ` (…)` at the end of the line that is not preceded by `]`, so a trailing markdown link `[x](https://…)` is never rewritten.
    - `index: missing`, `index: ambiguous`, or no `pages/Index.md`: nothing is written to Index, the rest of `save-finish` continues, and the output says what to do.
11. **The `--graph` guard applies to the start and end of text,** per spec §1.3. `activity` and `--summary` refuse text whose first or last word is `--graph` or `--graph=…`. Text like "fixed --graph parsing" is allowed.
12. **Composite `load` decides "has a digest" from the `map:` line** (printed only when a `## Digest` exists), not from the absence of `digest: missing`. A page that is not digest-bearing prints `digest: not applicable`. `load` then writes no activity line, and prints the same instruction as the no-digest path.
13. **`load --mode full`** prints:
    - the section table, via `run_awk sections` directly (so **no** baselines are recorded; `cmd_sections` always records them);
    - a `full-budget:` line: min(bytes, 8192) summed over Overview, Current Plan, Implementation and Decisions, plus min(Session Log bytes, 8192).

    It writes no activity line; the model writes `(full)` after its reads.
14. **`fix` hints are printed by the shell from a separate `hints.awk`,** over the rule names collected from both engines (`lint.awk` and `map.awk`'s digest lint).
    - `lint`: before its `summary:` line, after the findings. `summary:`'s by-rule counts are computed before the hints are appended, so they never contain a `fix` entry.
    - `check`: once, after the last file's summary line.
    - Each hint is printed once per rule, in first-seen order, as `fix <rule>: <hint>`.

- [ ] **Step 2: Replace the option loop.** This was prototyped in review, and is identical under dash and `bash --posix`:
  ```sh
  OPT_GRAPH=; _gset=0; _dd=0; _n=$#
  while [ "$_n" -gt 0 ]; do
    _a=$1; shift; _n=$((_n - 1))
    if [ "$_dd" = 1 ]; then set -- "$@" "$_a"; continue; fi
    case $_a in
      --)        _dd=1 ;;
      --graph)   [ "$_n" -ge 1 ] || die "--graph needs a directory"
                 [ "$_gset" = 0 ] || die "--graph given twice"
                 OPT_GRAPH=$1; _gset=1; shift; _n=$((_n - 1)) ;;
      --graph=*) [ "$_gset" = 0 ] || die "--graph given twice"
                 OPT_GRAPH=${_a#--graph=}; _gset=1 ;;
      *)         set -- "$@" "$_a" ;;
    esac
  done
  [ "$_gset" = 0 ] || [ -n "$OPT_GRAPH" ] || die "--graph needs a directory"
  cmd=${1:-help}; [ $# -gt 0 ] && shift
  ```

## Review log

Two independent reviews ran on 2026-09-25, before any implementation. One covered the helper and tests, prototyping the flag pre-pass and the awk regex handling on mawk, gawk and original-awk. The other covered the skills, evals and process. This revision adopted every confirmed finding.

**The ones that changed the design:**
- **`-v` regexes break on gawk and BWK awk.** Now a Global Constraint, with doubled backslashes and `ENVIRON` for names.
- **Five eval graders reject a trailing `--graph`.** Task 14 Step 1 is now tied to Task 2 and to the v0.11.1 fallback.
- **The `LOGSEQ_BRAIN_PATH` decoy cannot reach an eval run.** Task 14 Step 4 is redesigned around a config file, gated on Task 0 Step 6.
- **`save-finish` could die or double-write partway.** It now validates first (refinement 3), skips absent files (refinement 8), has an idempotent Sessions append (refinement 9), and a prefixed-locals rule.
- **Warn-only checks exit 0.** Refinement 4, and the `save-finish-warn-only` expectation.
- **Empty `--graph` fell through to the environment.** Refinement 2.
- **`fix` hints in `lint.awk` would corrupt the lint summary and miss the digest rules.** Refinement 14 and Task 9.
- **The skill rewrites were missing mandated behaviour:**
  - the Cowork `--graph` rule;
  - active tasks, the continuity hint and the journal coverage line on load;
  - decision detection on every save, the task `status::` and Decisions Edits, the multi-project order, and a late `--also`;
  - brain-doctor's catalog content.

  These are now explicit checklists in Tasks 10 and 11, and a "shipped skills never cite moved text" rule in Task 12.
- **Shell expansion of backticks in `--summary`.** The single-quote rule, plus Task 14 Step 5.
- **The size targets for `digest.md` and `hygiene-rules.md` were unreachable** without dropping shipped content. They are restated in the spec annotation.
