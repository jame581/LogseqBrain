# v0.12.0 Fewer Round Trips Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring a digest load from 11 tool calls to ≤ 4 (shape: 2) and a save from 27 to ≤ 13 (shape: 7). Fix the trailing `--graph` bug, which can write to the wrong graph. Make the routine load and save read nothing but their SKILL.md. The eval suite proves the call targets as pass criteria.

**Architecture:** Nothing new at the base. The dispatcher gains a flag pre-pass and three composite commands (`load`, `save-begin`, `save-finish`). Each is a shell function calling the existing `cmd_*` functions in one process. `save-finish` gains two writes under the existing verified single-change commit (`commit_write` + `onechange.awk`):
- the journal `## Sessions` bullet;
- the parenthetical of the page's `pages/Index.md` one-liner.

Skill prose is rewritten around the composites. Developer-only contract text moves out of `skills/` into `docs/reference/` (not shipped).

**Tech Stack:** unchanged from v0.11.0: POSIX `sh`, POSIX `awk`, base coreutils. Python 3 only in dev-only `tools/`. The eval suite runs in WSL2 as the `logseq-eval` user.

**Spec:** `docs/superpowers/specs/2026-09-25-v0.12.0-design.md`. Maintainer decisions D1–D5 were all accepted as recommended on 2026-09-25. Read the spec before starting; this plan argues from it.

## Global Constraints

Every task's requirements implicitly include this section.

- **Carried over from the v0.11.0 plan's Global Constraints, unchanged:**
  - Logseq OG only.
  - POSIX sh/awk only: no `gensub`, no three-argument `match`, no `strftime`/`systime`/`mktime`, no `length(array)`, no `{n,m}` intervals.
  - `LC_ALL=C`.
  - KB means KiB, truncated.
  - `-v BINMODE=3` on every awk.
  - Never `echo` user text (use `printf '%s'`).
  - Paths guarded.
  - Exit codes 0 / 1 / 2.
  - Graph-relative output (except `info`'s `graph:` line).
  - Invocation always through `sh`.
- **The helper writes exactly four kinds of line, all through `commit_write`:**
  1. the Map line (`digest --apply`);
  2. one activity bullet (`activity`);
  3. one `## Sessions` bullet (`save-finish --summary`, new);
  4. the one-liner's parenthetical in `pages/Index.md` (`save-finish --index`, new).

  Plus, for 2 and 3 only, the heading or the journal file when it must be created. Nothing else, ever. Every new write kind gets a refusal test and runs under the harness's write-safety assertion.
- **Claude-composed text the helper writes is linted before it is written.** `--summary` and `--index` text with an error-tier finding is refused (exit 1, finding printed, nothing written). Logseq parses a file as soon as it changes and never deletes a page it created, so a phantom page must be stopped before the write, not after.
- **Existing commands keep their exact output.** brain-doctor, brain-status, rotation and recovery paths still call them. Every one of the existing 78 golden cases stays green, unmodified, after every task.
- **Composite output is concatenated sub-command output,** each block headed by a `== <command>` line. No figure or coverage line is reformatted.
- **Never `git add -A`.** Always stage explicit paths.
- **Commit trailer** on every commit:
  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: <the implementing session's URL>
  ```
- **Branch:** `v0.12.0`, per repo convention. Create it from `main` after merging the branch that carries this plan and the spec (`claude/vigilant-bardeen-07hk40`). Conventional commits with a scope: `fix(brain):`, `feat(brain):`, `test(harness):`, `docs(brain-save):`, `test(evals):`.
- **The eval suite and anything touching the live graph are maintainer steps** (WSL2, plan usage, the maintainer's machine). Tasks mark them **[maintainer]**. An agent prepares the change and the exact commands, and does not claim a result it did not see.

## Deliberate refinements of the spec

Each was decided while planning. They are recorded here so that no implementer "fixes" them back to the spec's wording.

1. **`--` is consumed, not passed through.** `brain search -- --graph` reaches `cmd_search` as the single argument `--graph`. No command understands `--`, so passing it on would make it a search term.
2. **`save-finish` order is: `--summary` write → `--index` write → Map write → check → activity.** Both new writes happen before the check, so the check covers them. The Map is written after them, and they never touch the page.
3. **`save-finish` writes the activity line only when the check reports 0 new error-tier findings.** Otherwise it prints `activity: deferred — fix the errors above, then run: brain check <files> && brain activity "saved [[…]]"`. The journey log must not record a save as done while it still carries a new error. Warn-tier findings do not defer it.
4. **`save-finish` runs one check over the whole set.** It does not run `digest --apply`'s own internal page check, and then the set check again. `cmd_digest_apply` is split into a write part and a report part (Task 4) so that the composite can do this.
5. **The save set lives in a manifest,** `$STATE_DIR/save.lst`, written by `save-begin`. `save-finish` without a manifest, or with one older than 12 h (the baseline expiry), exits 2: `no save-begin for this graph in the last 12 h — run brain save-begin first`. A manifest naming a different page exits 2 as well: `save-begin was for Projects/Y`.
6. **`load` on `--mode full`** prints the section table (as `sections`, **without** recording baselines) plus a `full-budget:` line: the byte sum of Overview, Current Plan, Implementation and Decisions (each capped at 8 KB), plus the Session Log tail estimate capped at 8 KB. It writes `(full)` only after the model's reads. Its activity is left to the model, like the fallback's `(brief)`.
7. **`fix:` hints** are one line per finding kind, not per finding. They are printed after the findings block, in first-seen rule order, as `fix <rule>: <hint>`. This keeps `check`'s summary line, which the eval graders match, unchanged.
